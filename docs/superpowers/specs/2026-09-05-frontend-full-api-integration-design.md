# 全量后端接口前端接入设计

## 目标

将 `career-core` 中所有当前对外可用的 `/api/v1` 控制器接口，接入 `fronted` 的受角色保护页面。每个接口必须有可发现的页面入口、能提交其必要输入的交互、成功后的结果呈现，以及失败时的用户可读提示；不能只停留在 `api/request.ts` 中的未使用封装。

## 范围与约束

- 以 `career-core/src/main/java/**/controller/*Controller.java` 中的 HTTP 映射为接口唯一来源。
- 前端继续使用 Vue 3、Vue Router、TypeScript 和现有 `request()` 适配器；不改动后端 API 契约。
- 登录、刷新 token 和注销仍由现有会话恢复及路由守卫触发。刷新接口不另设用户操作按钮。
- 所有读写均复用 `request()` 的 JWT、刷新重试、请求 ID 与幂等键逻辑；文件下载复用 `downloadFile()`。
- UI 只对具备对应角色的用户显示；后端仍是权限的最终裁决者。
- AI 与 Gateway 接口继续请求后端网关，不在浏览器暴露模型密钥。

## 架构

```text
路由页面 / 对话框
  -> 领域 composable（加载、提交、busy/error、刷新）
    -> api.request.ts（完整、强类型的端点适配）
      -> /api/v1 后端
```

`request.ts` 是唯一 HTTP 边界。各页面不得拼接 `/api/v1`、自行处理 token 或吞掉异常。需要跨页面的异步状态通过 composable 管理；一次性管理配置页可保留在 `AdminWorkbenchView`，但必须按领域拆出请求和表单状态，避免继续膨胀。

## 信息架构与接口覆盖

### 学生端

现有“测评与发展”页保留为主工作区，补足以下细节入口：

| 工作区 | 控制器接口 | 交互与结果 |
| --- | --- | --- |
| 账户与隐私 | `auth/me` 读/改、`auth/me/password`、`auth/privacy-consent` 状态/提交、`students/me/deletion-request` | 资料、密码、授权、注销数据申请表单与即时反馈 |
| 档案与经历 | `students/me`、`completeness`、`experiences` 全部 CRUD | 现有档案/经历页面；每次保存刷新完整度 |
| 问卷与会话 | `questionnaires` 列表/详情/版本，`assessment-sessions` 新建/列表/详情/保存/提交/得分 | 问卷版本查看、继续未完成会话、得分详情 |
| 画像 | 最新、刷新、版本、单版本详情、反馈 | 历史版本可打开详情；反馈回显 |
| 方向与推荐 | 方向列表/详情、收藏列表/增删、推荐新建/最新/分页/详情/反馈 | 方向详情抽屉、推荐运行历史及单次结果详情 |
| 目标与计划 | 目标读/新建/变更/版本；计划最新/列表/详情/草案/确认/编辑 | 计划历史与编辑表单；确认后的状态回显 |
| 任务与复盘 | 任务列表/详情/新建/改动/打卡；复盘列表/详情/草稿新建/改草稿/提交/AI 总结/采纳建议/申请指导 | 任务详情、复盘编辑及“采纳/不采纳建议”操作 |
| 提醒 | 列表、未读数、标记已读、生成 | 筛选、已读状态和计数同步 |
| AI 助手 | AI 聊天、历史、指定消息反馈、最近消息反馈、推荐解释、计划生成、复盘总结、PDF 解析 | 学生工作区内的聊天/结果面板；管理端保留调试台 |

### 辅导员端

以“学生列表”为单一入口，详情对话框内加载学生总览、指导记录并提交指导意见/建议任务/建议重新测评。现有独立页面保留为筛选与快捷入口。

| 页面 | 控制器接口 |
| --- | --- |
| 工作总览、群体统计 | `advisor/statistics` |
| 学生列表和详情 | `advisor/students`、`advisor/students/{studentId}` |
| 重点关注 | `advisor/attention` |
| 指导记录 | `advisor/students/{studentId}/guidance` 读/写、`.../advice` 写 |

### 管理端

`AdminWorkbenchView` 改为按业务域渲染的表格、筛选器、创建/编辑对话框及任务进度面板；路由继续维持现有后台菜单，并新增“问卷”和“提示词”菜单项。

| 管理模块 | 控制器接口 |
| --- | --- |
| 用户与白名单 | `admin/users` 列表/更新；`admin/whitelist` 列表/新增/导入/删除；管理员密码重置 `auth/password/reset` |
| 师生关系 | `admin/relations` 列表/新增/删除 |
| 方向、能力、模板、权重 | 各自列表/新增/更新（方向另含状态切换） |
| 培养方案 | 文件导入、导入任务列表/详情、条目列表/审核/批量审核、版本列表、发布 |
| 问卷 | 列表/新增/编辑/状态、版本列表/详情/创建/发布 |
| AI 管理 | 模型配置列表/更新；提示词场景、列表、新版本、发布；AI 调用日志和操作日志 |
| 数据导出 | 导出任务列表/创建、下载已完成文件 |
| AI 调试 | `gateway/generate`、`gateway/chat/completions` 和所有 `ai/*` 接口，表单按契约输入并显示原始/格式化响应 |

## 前端接口层

1. 将 `api` 的所有响应从 `unknown` 收敛为领域 DTO；共享 `PageResult<T>`、列表查询参数和操作结果类型。
2. 补齐当前缺失的端点方法：任务详情、复盘详情/编辑/采纳建议、画像详情、推荐详情、方向详情、计划详情/编辑、培养方案和日志的列表端点、后台所有列表端点与导出下载。
3. 增加 `query` 辅助函数，仅编码已定义的可选参数，确保分页、过滤、排序以控制器参数名传递。
4. 下载和上传分别使用 `downloadFile` 与 `FormData`；上传在 UI 明确显示后端返回的任务 ID 与轮询状态。

## 失败处理与交互规则

- 每个提交按钮有独立的 `busy` 状态，重复点击被禁用。
- 每个读/写请求的错误以 toast 或就地错误块显示 `getErrorMessage()`；不会伪造成功结果。
- 写操作成功后只刷新受影响的列表、详情和计数；避免全页无条件重载。
- 需要 ID 的操作只能从当前已展示的记录触发；无法手工输入任意资源 ID。
- 异步培养方案导入按固定间隔轮询，完成、失败或组件卸载时停止。

## 测试与验收

1. 为 `request.ts` 的查询编码、授权重试、上传与下载加入 Vitest 单元测试。
2. 为每个领域 composable 写请求映射测试：断言页面操作调用正确 HTTP 方法、路径和请求体，并处理成功与失败。
3. 为路由与菜单写覆盖测试，保证学生、辅导员、管理员能发现其被授权的功能。
4. 新增一份控制器到 UI 的静态覆盖表；CI 测试读取该表并检查每个端点有路由/组件与 `api` 方法引用。
5. 通过 `npm test` 和 `npm run build`。在可运行后端时，按角色执行冒烟：学生完成测评到复盘、辅导员指导学生、管理员导入并发布、AI 调试台请求。

## 非目标

- 不修改后端接口、数据库、权限规则或模型供应商配置。
- 不为刷新 token、路由守卫这类自动流程添加误导性的人工按钮。
- 不为同一业务能力建立“仅供调用接口”的重复页面；开发调试例外是已存在的 AI 调试台。
