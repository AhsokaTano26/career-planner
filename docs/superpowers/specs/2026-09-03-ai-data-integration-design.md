# AI、测评与规划能力干净整合设计

## 目标

将 `origin/AI_and_DATA` 中可部署的 AI、测评、画像、推荐、规划能力整合至当前 `main` 的认证、管理与前端架构中；不引入报告、日志、浏览器产物或本地工具配置。

## 范围与边界

纳入：Spring 后端的 `ai`、`assessment`、`portrait`、`recommendation`、`planning`、方向收藏及管理端模型/提示词/问卷模块；对应 MySQL schema、种子数据、前端 API 和角色工作台页面。

排除：`tests/apifox-reports`、运行日志、临时导出、`.playwright-mcp`、个人技能/代理配置和其他非运行时文件。不会迁移旧版 `feature/student-profile-algorithm` 的无 JWT Demo 接口。

## 架构与数据流

浏览器只调用 Spring Boot 的 `/api/v1/**`。Spring 从 JWT 取得当前用户与角色，执行业务鉴权、脱敏、审计和持久化，然后通过内部令牌访问 `career-ai`。`career-ai` 不向浏览器直接暴露。新领域表由 Spring 的 schema 初始化脚本创建，现有数据保持不删改。

## 实施阶段

1. 建立可追溯的精选变更清单；先移植 schema、配置与后端领域模块，解决当前包名、认证、MyBatis 映射和初始化兼容性。
2. 为 AI、测评、画像、推荐与规划的核心授权路径补充或迁移测试；先验证失败，再完成实现与集成。
3. 将学生端接入测评、画像、推荐、目标计划、任务和复盘；管理员端接入模型配置、提示词、问卷和 AI 调试能力。保留现有角色路由与可访问性约束。
4. 在干净数据库上运行后端测试、前端测试和生产构建；运行 Docker Compose 配置校验。通过后才合并回 `main`。

## 兼容与安全要求

- 所有学生资源必须由 JWT 当前用户解析，禁止请求参数指定其他学生身份。
- AI 网关仅供 Spring 内部调用；密钥只从环境变量读取。
- 所有写操作继续使用既有幂等和审计约定。
- 数据库迁移只追加建表/种子，不删除现有表、用户或生产数据。
- 前端不得显示内部令牌、模型密钥或脱敏前的个人数据。

## 验收标准

- `main` 的三类身份既有功能不回归。
- 学生能够完成问卷、查看画像与版本、取得推荐、管理目标/计划/任务并提交复盘。
- 管理员可维护模型配置、提示词和问卷，且 AI 调试入口受管理员权限保护。
- 后端 Maven 测试、前端 Vitest、前端生产构建及 Docker Compose 配置校验均成功。
- 合并提交不包含上述排除的机器生成或个人环境文件。

## 风险处理

AI 分支是大规模同步提交，不能直接 merge。每批文件均以当前 `main` 的认证、包名和 schema 为准解决冲突；任何依赖已不存在表或缺少迁移的接口，必须先补迁移和测试，再接入页面。
