# 全站 UI 优化设计

**日期：** 2026-09-06
**状态：** 已确认，待实施计划
**范围：** `fronted` Vue 3 / Vite 客户端的登录、学生端、辅导员端、管理员端、状态页与共享组件。

## 目标

在不改变后端接口、路由、角色权限和业务流程的前提下，将现有页面提升为一致、可读、高效、响应式的重庆大学生涯发展工作台。重点是强化内容层级、数据工作流和交互反馈，而非引入装饰性视觉或重设品牌。

## 已确认的产品方向

- 保留“编辑型生涯档案 / 实验报告工作台”的信息架构：数据、进度、步骤、时间与状态优先于装饰。
- 保留重庆大学机构识别和现有硬朗线框语言；以 CQU 蓝为主品牌色，蓝色浅阶用于信息表面，深蓝用于导航与主操作。
- 不采用渐变、玻璃态、圆润卡片、拟人 AI 形象、无业务意义的插画或泛化营销式仪表盘。
- 全面覆盖学生、辅导员和管理员角色，而非只改高首页。

## 视觉系统

### 令牌与排版

将 `styles.css` 与 `cqu-theme.css` 的分散覆盖收敛为分层令牌：基础几何与排版令牌、CQU 品牌色令牌、语义状态令牌、组件状态令牌。最终视觉以当前 CQU 蓝主题为准，避免同时出现旧的荧光绿 / 橙红主状态和蓝色主题的语义冲突。

- 页面：低饱和浅蓝纸张底色、白色内容表面、深蓝黑字、清晰的 1px 分割线。
- 文字：中文无衬线承担内容层级；等宽字体只用于编号、元数据、状态与时间；标题采用紧凑的权重与字距，正文保障 1.5–1.7 行高。
- 形状：保持直角或极小圆角；不使用大面积阴影。层级主要由网格、分割线、背景阶和色带表达。
- 语义：主操作为深蓝；进行/信息使用蓝色浅阶；需注意的状态使用低频金色；危险操作采用明确文字加危险色，不能仅靠颜色。

### 共享组件规范

所有组件均需有默认、悬停、焦点可见、禁用、加载和窄屏状态。

| 组件 | 统一规则 |
| --- | --- |
| 应用壳层 | 宽屏固定侧栏 + 顶栏；中屏压缩为图标导航；手机提供可访问的展开式导航，不能隐藏主要入口。 |
| 页面标题 | 英文/元信息微标题、中文主标题、一句用途说明和底部分隔线；操作区在窄屏垂直堆叠。 |
| 按钮与图标操作 | 一个区域只有一个视觉最强的主操作；图标使用一致 SVG 或现有图标资源，不使用文本符号模拟图标。 |
| 表单与筛选 | 标签、说明、必填、校验、输入焦点和提交中状态统一；筛选条件可折行但结果和主操作始终可辨识。 |
| 表格与记录列表 | 保留工作台密度和列对齐；移动端将次级列折叠为行内元数据，而不是机械变为大卡片。 |
| 标签、状态与通知 | 文字、色彩和图形标记三者至少取二；通知有明确成功、提示、警告、失败语义。 |
| 弹窗与抽屉 | 保持任务上下文，提供键盘焦点管理、Esc 关闭、危险操作确认与保存中防重提交。 |
| 空/加载/错误 | 采用与数据区域同尺寸的可读占位，说明原因、可执行下一步和必要的重试操作。 |

## 按角色的页面策略

### 学生端

突出连续成长路径：档案完善 → 测评 → 画像与推荐 → 目标/计划 → 任务/复盘。概览页以进度和下一步行动为第一层；发展页用清晰的工作流分段承接密集操作；档案、经历与隐私页采用结构化记录而非零散信息卡片。空状态必须给出可直接抵达的下一步。

### 辅导员端

优先支持决策与学生跟进：筛选条件、风险/关注信号、学生摘要、指导历史和群体统计应在视觉上可快速扫描。保留表格、时间线和筛选组合的密度；学生详情以可比较的指标、记录和待办组织，避免营销式 KPI 卡片。

### 管理员端

将高密度配置工作统一为“标题与上下文 → 筛选/批量操作 → 数据表或配置内容 → 分页/审计记录”节奏。清晰区分草稿、已发布、已停用、处理中、失败、不可逆操作以及 AI 生成内容；导入、导出、版本、日志和权限相关任务必须持续可追溯。

### 认证与状态页

登录页、权限拦截、404 与系统错误页共享同一品牌栅格、排版和行动按钮规则。错误页提供返回安全入口、错误上下文与可恢复操作，不展示无用技术细节给普通用户。

## 响应式与动效

- 断点策略：宽屏保留侧栏与表格列；中屏压缩导航和次要信息；小屏采用单列阅读、可展开导航和底部/就近主操作。
- 所有页面避免固定宽度溢出；长名称、状态串、表格内容和弹窗正文必须可换行或可滚动。
- 动效仅用于路由切换、列表进入、进度更新、弹窗及操作反馈；时长短、位移小，并遵循 `prefers-reduced-motion`。
- 不使用持续动画、自动播放的装饰效果或会妨碍数据阅读的入场动画。

## 功能与性能约束

- 不修改 API 请求模型、路由路径、权限逻辑、业务文案含义或现有核心流程。
- Vue 组件保持职责集中：共享外观放入基础组件/样式层，页面仅负责业务组合与状态。
- 不新增大型 UI 组件库；复用项目现有组件和原生 Vue/CSS 能力。
- 不因视觉改造引入不必要的图片、图标包、轮询或大体积依赖。
- 动态页面和长列表只渲染必要内容，保留现有加载/错误处理并减少不必要的响应式重渲染。

## 验收标准

1. `npm run build` 和可运行的前端测试通过；如本机环境存在无关测试限制，须单独记录。
2. 在桌面与 375px 左右手机宽度检查登录、学生概览/发展、辅导员学生列表/详情、管理员工作台与状态页。
3. 验证三条核心流程：学生编辑档案并保存；辅导员筛选学生并进入指导；管理员筛选/编辑一项配置并接收反馈。
4. 全站检查加载、空数据、错误、保存中、禁用、焦点可见和危险确认状态。
5. 对比优化前后截图，至少审查标题层级、侧栏、表格/列表密度、表单焦点、移动端导航、状态色和操作反馈七项。
6. 无横向溢出、无法访问的键盘焦点、不可读的颜色对比、文本图标替代关键图标、或不一致的组件状态。

## 涉及的主要代码边界

- 全局基础：`fronted/src/assets/styles/styles.css`、`cqu-theme.css`、`functional.css`、`lists.css`、`motion.css`。
- 布局与基础组件：`DefaultLayout.vue`、`AdminLayout.vue`、`BasePageHeader.vue`、`BaseModal.vue`、`BaseSelect.vue`、`RouteTransition.vue`。
- 页面：`views/AuthView.vue`、`views/student/*`、`views/advisor/*`、`views/admin/*`、`ErrorView.vue`、`NotFoundView.vue`。
- 只允许为可复用的视觉/交互原语新建组件；不得以全局 CSS 覆盖堆叠替代明确的组件边界。
