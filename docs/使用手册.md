# 生涯规划系统 · 使用手册

> 适用版本：MVP V1.0（Demo） ｜ 最后更新：2026-08-15
> 本手册面向**部署 / 运维 / 二次开发人员**，说明如何在本地把系统跑起来、验证、调用接口与部署。
> ⚠️ 前端（Vue 3）目前为**空骨架**，尚无图形界面；当前一切功能均通过 **HTTP 接口**使用。

---

## 一、系统简介

「计算机与软件大类新生生涯规划系统」用于帮助学生完成 **注册 → 测评 → 画像 → 方向推荐 → 目标计划 → 任务 → 复盘 → 指导** 的生涯规划闭环。

### 1.1 总体架构

```text
Browser（Vue3，未实现）──▶ Nginx ──▶ career-core（Spring Boot，:8080）──▶ MySQL（:3306）
                                        │
                                        └─ internal HTTP ──▶ career-ai（FastAPI，:8000）──▶ LLM（DeepSeek）
```

| 组件 | 技术栈 | 端口 | 职责 | 现状 |
|------|--------|------|------|------|
| `career-core` | Spring Boot 3.5 + Java 25 + MySQL + JdbcTemplate | 8080 | 唯一的鉴权、规则、事务、正式数据写入入口 | ✅ 已实现（画像 / 推荐 / 计划 / AI 解释） |
| `career-ai` | FastAPI（Python） | 8000 | 智能服务：接收最小化结构化输入，调用大模型返回解释 | ✅ 已实现（推荐解释），其余为占位骨架 |
| `frontend` | Vue 3 | - | 按角色加载学生 / 辅导员 / 管理员布局 | ⚠️ 空骨架，未实现 |
| `deploy` | Docker Compose + Nginx | 80 | 部署编排 | ⚠️ 最小骨架 |

### 1.2 设计边界（重要）

- `career-core` 是唯一写正式业务库的服务；`career-ai` **不连接 MySQL、不持有学生身份信息、不写入业务表**。
- 方向排序由**规则引擎**决定；AI 只生成受约束的**解释 / 草案 / 总结**，AI 不可用时自动回退规则模板。
- Demo 阶段**无登录态**：接口以可选参数 `studentId` 指定学生，缺省取 `1001`。

## 三、快速开始（本地一键跑通）

按顺序执行以下步骤即可跑通全链路：

1. 启动 MySQL（见 3.1）
2. 构建并启动 `career-core`（见 3.2）
3. 配置并启动 `career-ai`（见 3.3）
4. 运行冒烟测试验证（见 3.4）

### 3.1 启动 MySQL

本机 MySQL 非 Windows 服务，需手动启动：

```powershell
& D:\devtools\mysql\mysql-26.7.0-winx64\bin\mysqld.exe --defaults-file=D:\devtools\mysql\my.ini --console
```

确认监听正常：

```powershell
Test-NetConnection 127.0.0.1 -Port 3306
```

**库与账号**：

| 项 | 值 |
|----|----|
| 数据库名 | `career_core` |
| 账号 / 密码 | `career` / 由环境变量 `DB_PASSWORD` 注入（缺省 `career123`） |
| 编码 | utf8mb4 |

> 建表与种子数据在 `career-core` 启动时自动执行
> （`src/main/resources/db/migration/schema.sql`、`data.sql`，幂等、可重复启动），**无需手动建表**。

### 3.2 构建并启动 career-core（后端，:8080）

```powershell

# 2. 进入后端目录并打包

# 3. 启动（后台常驻）

```

启动成功标志：日志出现 `Started CareerCoreApplication`，访问 `http://127.0.0.1:8080` 有响应。

### 3.3 配置并启动 career-ai（智能服务，:8000）

```powershell
# 1. 进入 career-ai 目录，准备虚拟环境与依赖（首次）
cd D:\Zht20241287\career-planner\career-ai
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2. 配置大模型密钥（首次）：复制 .env.example 为 .env 并填入真实 Key
#    LLM_API_KEY=<你的 DeepSeek Key>
#    LLM_BASE_URL=https://api.deepseek.com
#    LLM_MODEL=deepseek-v4-pro

# 3. 启动服务
.\.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

健康检查：

## 四、功能使用说明（接口）

> Demo 无前端，以下通过 `curl` / `Invoke-RestMethod` 演示。
> 所有接口统一前缀 `/api/v1`；**成功响应为裸业务对象**（无 `{code,message,data}` 包装），**错误响应**统一为 `{code, message, data}`。

### 4.1 学生画像

查看最新画像：

```powershell
curl "http://127.0.0.1:8080/api/v1/students/me/profile/latest?studentId=1001"
```

- 返回：`{ dimensions(六维), summary, version, completeness, studentId, experiences }`
- 学生不存在 / 画像未生成 → HTTP 404（`code=40400`）

画像版本列表：

```powershell
curl "http://127.0.0.1:8080/api/v1/students/me/profile/versions?studentId=1001&page=1&size=20"
```

### 4.2 方向推荐（核心模块）

**① 创建推荐批次**（触发三段式：规则过滤 → 结构化评分 → AI 解释）：

```powershell
curl -X POST "http://127.0.0.1:8080/api/v1/students/me/recommendations/runs?studentId=1001" `
  -H "Content-Type: application/json" `
  --data-binary @- <<'EOF'
{"pathFilter":"employment","requestId":"req-20260815-001"}
EOF
```

**② 查询最新推荐结果**：

```powershell
curl "http://127.0.0.1:8080/api/v1/students/me/recommendations/latest?studentId=1001"
```

返回结构（关键字段）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `runId` | string | 推荐批次 ID |
| `status` | string | `RUNNING` / `SUCCESS` |
| `results[].directionId` | string | 方向 ID |
| `results[].rank` | integer | 排序名次 |
| `results[].score` | number | 匹配度评分（0-100） |
| `results[].confidence` | number | 归一化概率（0-1，Top 求和≈1） |
| `results[].reason` | string | 推荐理由（AI 生成，含 Holland 契合度与「建议加强」差距提示） |

> AI 解释为逐方向一次 LLM 调用，`/latest` 可能耗时数十秒，请耐心等待（冒烟脚本超时已放宽至 120s）。

**③ 推荐批次历史**：

```powershell
curl "http://127.0.0.1:8080/api/v1/students/me/recommendations?studentId=1001&page=1&size=20"
```

**④ 推荐批次详情**（`RUNNING` 时轮询此接口）：

```powershell
curl "http://127.0.0.1:8080/api/v1/recommendation-runs/{runId}"
```

**⑤ 推荐反馈**：

```powershell
curl -X POST "http://127.0.0.1:8080/api/v1/recommendation-results/{resultId}/feedback" `
  -H "Content-Type: application/json" `
  --data-binary '{"feedbackType":"HELPFUL","comment":"推荐很准"}'
```

### 4.3 目标计划

生成计划草案（复用最新推荐数据）：

```powershell
curl -X POST "http://127.0.0.1:8080/api/v1/students/me/plans/draft?studentId=1001" `
  -H "Content-Type: application/json" `
  --data-binary '{"directionId":"employment_backend","useAi":true,"requestId":"req-20260815-002"}'
```

- `directionId` 缺省取推荐第一名；`useAi=true` 时优先走 AI 生成（AI 不可用则回退规则模板）。
- 返回：`{ goalSummary, direction, semester, status=DRAFT, tasks[] }`，落库 `student_goal` / `semester_plan` / `plan_task`。

### 4.4 AI 智能服务（career-ai 直连，调试用）

```powershell
# 健康检查
curl http://127.0.0.1:8000/health

# 推荐解释
curl -X POST http://127.0.0.1:8000/v1/recommendation/explain `
  -H "Content-Type: application/json" `
  --data-binary @body.json
# body.json 示例见 career-ai/api/main.py 的 ExplainRequest 定义
```

## 五、通用约定

### 5.1 响应格式

- **成功**：HTTP 200，直接返回业务对象（与线上 Apifox 契约对齐）。
- **失败**：HTTP 4xx/5xx，`{ code, message, data }`，如 `{"code":40400,"message":"学生不存在或画像未生成","data":null}`。

### 5.2 错误码对照

| HTTP | 含义 |
|------|------|
| 400 | 参数校验失败 |
| 401 | 未登录 / 令牌失效（Demo 未启用） |
| 403 | 数据范围不足 |
| 404 | 资源不存在 |
| 409 | 业务状态不允许 |
| 503 | 智能服务不可用（已降级或可重试） |

### 5.3 幂等

写接口接收 `Idempotency-Key` / `requestId`（UUID），服务端以 `user_id + endpoint + key` 保证同一成功请求只生效一次。

## 六、配置说明

### 6.1 career-core（`application.yml`）

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `server.port` | 8080 | 服务端口 |
| `spring.datasource.url` | `jdbc:mysql://127.0.0.1:3306/career_core` | 数据库连接 |
| `spring.datasource.username` | `${DB_USERNAME:career}` | 数据库账号 |
| `spring.datasource.password` | `${DB_PASSWORD:career123}` | 数据库密码（环境变量注入，勿硬编码） |
| `career.ai.enabled` | `true` | 是否启用 AI 解释；关闭或失败自动回退模板 |
| `career.ai.base-url` | `http://127.0.0.1:8000` | career-ai 地址 |
| `career.ai.connect-timeout-ms` | 2000 | 连接超时（AI 挂掉时快速回退） |
| `career.ai.timeout-ms` | 15000 | 读取超时（真实 LLM 需数秒，**勿调小**） |
| `career.ai.model` | `deepseek-v4-pro` | 期望模型名（仅记录，实际由 career-ai 决定） |

### 6.2 career-ai（`.env`）

| 变量 | 说明 |
|------|------|
| `LLM_API_KEY` | 大模型 API Key（必填，缺省则解释接口 502、自动降级） |
| `LLM_BASE_URL` | 大模型 Base URL（默认 `https://api.deepseek.com`） |
| `LLM_MODEL` | 模型名（默认 `deepseek-v4-pro`） |

## 八、常见问题与排坑

| 现象 | 原因 / 处理 |
|------|-------------|
| `mvn` 命令找不到 / 编译报错 | 新终端未读到 User 级 `JAVA_HOME`；先执行第 3.2 节的环境变量设置 |
| 启动后中文乱码 / 伪空格 | PowerShell 管道把 UTF-8 按 GBK 解码；用 `curl.exe -o 文件` 存原始字节 + `Get-Content -Encoding utf8` 查看，或查库用 `SELECT HEX(col)` |
| curl 发 JSON 返回 500 | PowerShell 中 `curl -d "{\"...\"}"` 的 `\"` 不会转义；改用 `--data-binary @文件` |
| 推荐理由总是模板、无 AI 文本 | career-ai 未启动或 `LLM_API_KEY` 未配置（查看 career-core 日志的 `career-ai 解释生成失败，回退规则模板理由` WARN）；或读取超时过小（保持 ≥15s） |
| `/latest` 请求很慢 | 每条方向一次 LLM 调用属正常；超时放宽到 120s |
| MySQL 保留字报错 | 8+ 中 `rank` 为保留字，SQL 需写成 `` `rank` `` |
| 重复启动报表已存在 | 脚本幂等，可重复执行；如中途改过结构，先看 `db/migration/schema.sql` 的幂等逻辑 |
