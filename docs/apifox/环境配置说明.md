# Apifox 调试环境配置说明

本说明供团队本地调试使用。系统有两个后端服务，需分别建两个 Apifox 环境：

| 环境 | 端口 | 前置脚本 | 鉴权方式 |
|------|------|----------|----------|
| `career-core` | 8080 | `pre-request-auto-login.js` | 学生/辅导员/管理员 JWT（脚本直接注入 Authorization 头）|
| `career-ai` | 8000 | `pre-request-career-ai.js` | 网关静态密钥 `GATEWAY_API_KEY`（Bearer 注入）|

> 前端开发服务器在 5173，仅代理 `/api` → 8080；所有接口调试走上面两个后端环境即可。

---

## 一、career-core 环境（8080）

### 环境变量
| 变量名 | 值 | 说明 |
|--------|-----|------|
| `BASE_URL` | `http://127.0.0.1:8080` | career-core 地址 |
| `LOGIN_ACCOUNT` | `2026011301` | 学生账号；调管理员接口改为 `admin` |
| `LOGIN_PASSWORD` | `202601` | 学生密码；管理员为 `Admin@2026` |
| `ACCESS_TOKEN` | （留空） | 脚本自动写入 |
| `ACCESS_TOKEN_EXPIRES_AT` | （留空） | 脚本自动写入 |

可用调试账号：
- 学生：`2026011301 / 202601`、`2026011309 / 202609`、`2026011310 / 202610`
- 辅导员：`A2026001 / Adv@2026`
- 管理员：`admin / Admin@2026`

### 前置脚本（`pre-request-auto-login.js`）
脚本现在**直接用 `pm.request.headers.upsert` 注入 Authorization 头**，不再依赖 Auth 标签。
这样即使 Auth 标签的 BearerAuth 没绑定到请求，请求也会带上 token。
跳过登录/注册/刷新/SMS/健康检查等不需要 token 的接口。

```javascript
// pre-request-auto-login.js
const baseUrl  = pm.environment.get("BASE_URL");
const account  = pm.environment.get("LOGIN_ACCOUNT");
const password = pm.environment.get("LOGIN_PASSWORD");
const TOKEN_VAR  = "ACCESS_TOKEN";
const EXPIRE_VAR = "ACCESS_TOKEN_EXPIRES_AT";

const urlStr = (pm.request.url && pm.request.url.toString) ? pm.request.url.toString() : String(pm.request.url);

var skipAuth = /\/auth\/(login|register|refresh|sms|captcha)/.test(urlStr)
            || /\/health(\b|\/)/.test(urlStr)
            || /\/actuator\//.test(urlStr)
            || /\/v3\/api-docs/.test(urlStr)
            || /\/doc\.html/.test(urlStr);
if (skipAuth) return;

var tk    = pm.environment.get(TOKEN_VAR);
var expAt = parseInt(pm.environment.get(EXPIRE_VAR) || "0", 10);
var valid = tk && expAt > Date.now() + 5000;

if (valid) {
  pm.request.headers.upsert({ key: "Authorization", value: "Bearer " + tk });
  console.log("[pre] 已注入 Authorization（缓存，未过期）");
  return;
}

console.log("[pre] ACCESS_TOKEN 不存在或已过期，开始自动登录...");
if (!baseUrl || !account || !password) {
  console.error("[pre] 缺少环境变量 BASE_URL / LOGIN_ACCOUNT / LOGIN_PASSWORD");
  return;
}

pm.sendRequest({
  url: baseUrl + "/api/v1/auth/login",
  method: "POST",
  header: { "Content-Type": "application/json" },
  body: { mode: "raw", raw: JSON.stringify({ account: account, password: password }) }
}, function (err, res) {
  if (err || !res) { console.error("[pre] 登录请求失败:", err); return; }
  var json = res.json();
  var tok = json && json.data && (json.data.accessToken || json.data.token);
  if (!tok) { console.error("[pre] 登录失败:", JSON.stringify(json)); return; }
  pm.environment.set(TOKEN_VAR, tok);
  var exp = (json.data && json.data.expiresIn) || 7200;
  pm.environment.set(EXPIRE_VAR, String(Date.now() + (exp - 60) * 1000));
  console.log("[pre] 已自动登录并写入 ACCESS_TOKEN，expiresIn=" + exp + "s");
});
```

### 安装
1. 新建环境 `career-core`，填入上表 5 个变量（`ACCESS_TOKEN` / `ACCESS_TOKEN_EXPIRES_AT` 留空）。
2. **Auth 标签不用动**——脚本会强制注入；保留默认 `Inherit` 或 `No Auth` 均可。
3. 把脚本贴到「项目设置 → 前置脚本」（或目录级前置脚本）。
4. 之后任意接口自动带 `Authorization: Bearer <token>`，无需手动填。

### 首次使用注意（2026-08-30 升级）
- **第一次 Send 任意业务接口**（如问卷列表）时，`ACCESS_TOKEN` 为空 → 脚本触发异步自动登录
- 但 `pm.sendRequest` 回调是**异步**的，本次请求的 Authorization 还没注入就发出去了 → 会返回 401
- **第一次失败后，再点一次 Send**，此时 `ACCESS_TOKEN` 已经被异步回调写入，请求会带上 token → 200 OK
- 或者更稳：**先 Send 一次 POST `/auth/login`**（脚本直接放行不动 token），把响应里 `data.accessToken` 手动粘到环境变量 `ACCESS_TOKEN`，再 Send 业务接口就一次过

## 二、career-ai 环境（8000）

### 环境变量
| 变量名 | 值 | 说明 |
|--------|-----|------|
| `BASE_URL_AI` | `http://127.0.0.1:8000` | career-ai 地址 |
| `GATEWAY_API_KEY` | （复制自 `career-ai/.env` 的 `GATEWAY_API_KEY` 真实值）| **勿入仓、勿外泄**，仅本地调试用 |

> `GATEWAY_API_KEY` 真实值见 `career-ai/.env` 的 `GATEWAY_API_KEY=` 一行。

### 前置脚本（`pre-request-career-ai.js`）
```javascript
const key = pm.environment.get("GATEWAY_API_KEY");
if (key) {
  pm.request.headers.remove("Authorization");
  pm.request.headers.add({ key: "Authorization", value: "Bearer " + key });
}
```

### 安装
1. 新建环境 `career-ai`，填入上表 2 个变量（`GATEWAY_API_KEY` 从 `.env` 复制真实值）。
2. 把脚本贴到该环境所属前置脚本。
3. 调用时自动带 `Authorization: Bearer <GATEWAY_API_KEY>`。

### 接口与密钥关系
- **需要密钥**：`/v1/chat/completions`、`/api/v1/gateway/generate`（对应 `routes_gateway.py` 的 `_require_gateway_key`）。缺密钥返回 `401`。
- **不需要密钥**：`/api/v1/ai/*`（chat / recommendation/explain / plan/generate / review/summarize / pdf/parse）由服务内部持密钥调大模型。
- `career-core` 侧的 `/api/v1/ai/*` 由 core 内部转发到 8000，走 8080 环境即可。

## 三、常见排错
- 打到 8000 却返回 `{"detail":"Not Found"}`（FastAPI 默认 404）：请求发错了服务/端口，career-core 接口应走 8080 环境。
- 8080 返回 `401 AUTH_REQUIRED`：
  1. 确认选了「开发环境」(career-core)；
  2. 确认前置脚本已保存生效（项目/目录级前置脚本编辑后记得点保存）；
  3. 第一次 Send 后看「控制台」是否打印 `[pre]` 日志；
  4. 如果「控制台」显示 `[pre] 缺少环境变量 BASE_URL ...」，先回环境管理核对变量名（**区分大小写**）。
- 8000 网关接口返回 `401`：检查 career-ai 环境的 `GATEWAY_API_KEY` 是否与 `career-ai/.env` 一致。
- AI 类接口返回 `502/503`：大模型密钥（`career-ai/.env` 的 `LLM_API_KEY`）无效或网络不通，career-core 侧会按规则模板兜底，不影响数据调试。
- 端口转发导致 urlStr 替换失效：当前在脚本里用 `pm.request.url.toString()` 抽取全 URL，匹配 `/auth/login` 与目标路径，避免 host 被前置 URL 替换导致误判。
