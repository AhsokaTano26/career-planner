# 第一部分 帮助文档（https://docs.apifox.com/help）

## 1 入门

### 1.1 介绍（产品介绍）

> 来源：https://docs.apifox.com/introduction.md

以往，开发团队在进行 API 设计、管理和测试时，常常需要在多个工具（比如 Postman 和 Swagger）之间频繁切换。这种方式不仅容易导致数据同步不一致，还阻碍了团队成员之间的协作，最终影响开发效率。

**Apifox 正是这样一个平台**。它集 API 设计、API 开发、API 调试、API 管理、 API 文档、API Mock 和自动化测试等功能于一体，为 API 项目提供一站式解决方案。

**Apifox 如何整合你的工作流：**

- **API 设计者**：可以通过可视化界面创建 API，或者导入现有的 OpenAPI/Swagger 文件，甚至可以使用迭代分支来设计 API。
- **前端开发**：不再需要等待后端完成开发，可以直接基于 API 定义生成 Mock 数据，独立进行前端开发工作。
- **测试工程师**：可以基于同样的 API 定义自动生成接口用例，可视化编排测试场景，可轻松集成到 CI/CD 流水线。
- **API 文档维护者**：Apifox 一键生成规范的 API 文档，文档会随着 API 定义的更新自动保持同步。
- **性能测试人员**：在同一平台上进行专门的性能测试，无需切换工具。

**Apifox 丰富且强大的功能**：

1. 自动生成请求参数与请求体
2. 自动校验响应
3. 可视化断言和变量提取
4. 兼容 Postman 脚本
5. 执行数据库操作
6. 将请求保存为接口用例
7. 调用外部程序
8. 兼容微服务场景
9. 自动生成 Mock 数据
10. 将快捷请求保存为接口
11. 可视化编排测试场景
12. 自托管 Runner Mock

### 1.2 页面布局

> 来源：https://docs.apifox.com/page-layout.md

Apifox 的主界面大致分为以下几个部分：

- 头部区域
- 侧边栏
- 工作区（目录树、标签页、环境选择器）
- 底部区域

**头部区域主要功能**：
- 主窗口：进入个人主页
- 项目标签：每个标签代表一个项目
- 刷新：重新加载当前项目数据
- 设置：调整本地客户端设置
- 通知：显示团队活动提醒
- 头像：账号设置、访问令牌

**侧边栏主要功能**：
- 项目图标：跳转到团队与项目
- 接口管理：核心界面，可新建接口、发送请求、新建数据模型等
- 自动化测试：新建测试场景、查看测试报告
- 分享文档：分享给同事或发布文档站
- 请求历史：查看并重新发送所有已发送的请求
- 项目设置：所有与当前项目相关的设置
- 邀请成员

**工作区-目录树**从上到下包括：
- 分支与版本：默认主分支
- 搜索与过滤：只能搜索接口名称
- 新建：创建接口、快捷请求、数据模型、Markdown 等
- 项目概览
- 接口
- 数据模型
- 组件库
- 快捷请求

**工作区-标签页**类型：接口、数据模型、响应组件、Markdown、目录、快捷请求、WebSocket、项目概览、新建…

- **单击**打开目录树元素：标题**斜体**显示（临时标签页），再点击其他元素会被覆盖
- **修改内容后**：标题变为**常规字体**（固定标签页），再点击会打开新标签
- **双击**目录树元素：直接以常规字体打开（固定标签页）

**底部区域**从左到右：折叠/展开、在线状态、Agent、Cookie 管理、回收站、文档 & 交流群。

### 1.3 基本概念

> 来源：https://docs.apifox.com/apifox-basic-concepts.md
> 另见：https://docs.apifox.com/design-and-request-mode.md

**文档模式 vs 调试模式**（左下角切换）：

- **文档模式**：Apifox 推荐的模式，适合 API 设计优先的团队。编辑 API 文档和发送请求通过不同 Tab 进行（`修改接口` 改定义 / `运行` 发请求）。这种分离适合 API 设计者和开发者有明确角色分工。
- **调试模式**：特别适合没有事先定义 API 文档的团队（后端先完成代码，再生成文档）。开发者无需事先指定 API，可直接输入请求，保存后请求自动解析为接口文档。

**核心概念**：

- **接口**：Apifox 以 API（接口）为核心，所有操作都从定义 API 开始。Apifox 是一种基于 OAS（OpenAPI Specification）的扩展，可直接调试和保存请求。
- **快捷请求**：不基于 API 定义进行设计，类似 Postman 请求。也可将成功的请求保存为接口文档。
- **测试场景**：当需要批量发送请求时使用，由一系列测试步骤组成，支持从接口或接口用例中导入步骤，支持 If、for、forEach 等流程控制。
- **环境**：包含「前置 URL」和「变量」两个核心要素。切换环境时，前置 URL 和环境变量都会更新。
- **模块**：项目中使用模块对接口进行组织。模块与"服务"概念类似，每个模块有一套相关的业务接口、组件、前置 URL。

> ⚠️ **关键概念**：**前置 URL 是接口请求地址中的基础部分**，与接口路径拼接后构成请求最终发送的完整 URL。一个环境可以配置多个前置 URL（每个模块一个），以支持多服务、微服务架构。
> 
> 这与 OpenAPI（Swagger）规范一致，**不推荐**用 `{{BASE_URL}}` 变量代替。

- **项目**：模块（接口、组件）、环境、测试场景等的集合构成项目。Apifox 项目 ≈ Postman 的 Workspace，项目中的一个模块 ≈ 一个 Collection 文件夹。

## 2 快速上手

### 2.1 新建接口

> 来源：https://docs.apifox.com/create-api.md

新建接口的完整流程（以"通过 ID 查询宠物信息"为例）：

1. **新建接口**：点击 `新建接口` 创建一个新接口
2. **定义请求路径**：在接口路径栏中输入 `/category/{id}`
   - 名称：通过 ID 获取类别
   - Path 参数：参数名 `id`，类型 `integer`，示例值 `1`
3. **设置响应结构**：滚动至 `返回响应` 部分，在"成功(200)"响应下，点击"+"创建一个名为 "data" 的字段
4. **引用数据模型**：选中"data"字段，将类型设置为 `Object`，并选择"引用模型"，从列表中选择 "Category" 或相关数据模型
5. **添加响应示例**：在 `响应示例` 部分，点击 `添加示例`
6. **生成示例数据**：为示例命名，点击 `自动生成` → `确定`
7. **保存接口**：点击 `保存` 按钮

### 2.2 发送接口请求

> 来源：https://docs.apifox.com/send-api-request.md

接口创建完成后即可发起请求：

1. 在 **"文档模式"** 下，切换到 **"运行"** 标签页
2. 在右上角选择环境为 **"本地 Mock"**（或你配置的后端环境）
3. 点击 **"发送"** 按钮
4. 在 **"返回响应"** 区域查看请求结果
5. 切换到 **"实际请求"** 查看实际发送的请求
6. 点击 **"保存为用例"** 将此请求保存为接口用例

> 💡 如果需要向测试环境、开发环境或生产环境发送接口请求，将对应服务的 URL 填入右上角环境管理中的"前置 URL"。

### 2.3 发送快捷请求并保存为接口

> 来源：https://docs.apifox.com/quick-request.md

如果不希望提前定义接口文档，可以先发送快捷请求再保存为接口：

1. 点击左侧边栏的 `+` → `快捷请求`（或在标签页中新建）
2. 填写请求信息（方法、URL、参数、授权等）
3. 点击"发送"查看响应
4. 点击"保存为接口"按钮
5. 保存后可查看接口文档，实际发送的请求和响应将成为接口的示例，数据结构会被自动解析和生成

> 提示：cURL 命令可直接粘贴到地址栏，Apifox 会自动解析。

## 3 团队入驻指南

### 3.1 从 Postman 迁移

> 来源：https://docs.apifox.com/import-postman.md

**概念对照**：
- Postman 的 `Collection` 对应 Apifox 的 `项目`
- Postman 的 Collection 变量对应 Apifox 项目中的全局变量
- Postman 用变量存储 baseURL，Apifox 中前置 URL 独立存储在"环境管理"中的"服务"里

**导出 Postman 数据**：
1. **导出 Collection**：打开 Postman 左侧 Collections，点击 `···` → `Export` → 选 Collection v2.1 → 存为 `.json`
2. **导出 Environment**（可选）：打开 Environments → 找到目标环境 → `···` → `Export` → 存为 `.json`
3. **导出 Workspace 数据**（可选）：右上角头像 → Settings → Account → Export Data → Request Data Export

> ⚠️ Data Dump 主要用于备份和 Postman 内部恢复场景，不推荐用于迁移至 Apifox。

**导入到 Apifox**：
1. 打开 Apifox 中的"项目设置"面板，点击"导入数据"，选择 Postman 并上传文件
2. 在导入预览页中查看 Collection 下的所有接口
3. 在"环境"页中勾选与 Collection 同名的环境
4. 点击"确定导入"

### 3.2 导入 OpenAPI/Swagger

> 来源：https://docs.apifox.com/import-openapi-swagger.md

Apifox 支持导入 OpenAPI 3.0、3.1 或 Swagger 2.0 数据格式的 JSON 或 YAML 文件。

**选择接口维护方式**：
- **以可视化界面维护接口**（默认）：导入为可在界面中编辑的项目数据
- **以 OpenAPI 文件维护接口**（spec 模式，Beta）：将导入的文档作为规范文件创建 spec 模式项目

**导入选项**（可视化导入）：
- **目标分支**：选择工作分支（通常默认 main）
- **导入到**：可选择导入到已有模块或新建模块
- **自动生成接口用例**：为每个接口自动生成一个默认"成功"用例
- **导入 Servers 为环境**：将不同的服务器地址自动创建为不同环境
- **导入 Security Scheme**：将 API Key、Basic Auth 等导入到 Apifox 的 Auth
- **接口 Summary 为空**：默认使用 `operationId` 作为名称，也可使用 path
- **资源冲突处理**：
  - **覆盖已有接口**：新接口完全替换旧接口
  - **保留两者**：两个接口都保留
  - **不导入**：忽略新接口
  - **智能合并**：保留旧接口的中文名、Mock 规则、参数说明和响应示例
  - **覆盖指定字段**：只覆盖选中字段
- **目录同步**：是否更新接口目录
- **资源清理**：是否删除新文件中不存在的旧资源

**URL 导入**：填写 `.json` 或 `.yaml` 数据文件的 URL（直链），而非 Swagger UI 的 URL。

**定时导入**：进入"项目设置 → 导入数据"，切换到"定时导入"选项卡。

### 3.3 团队入驻与协作

> 来源：https://docs.apifox.com/onboard-team.md

**和 IT 团队对接**：
- 设备管理策略中添加 Apifox 的白名单
- 如有代理，Apifox 中配置代理信息（已登录用户：右上角 ⚙设置 → 网络代理；未登录用户：登录界面左下角）
- 防火墙需把以下域名加入白名单：`*.apifox.com`、`*.apifox.cn`

**团队设置**：
- 团队管理员注册账号后可创建团队，自动成为"团队所有者"
- 团队所有者权限：修改团队信息、创建项目、管理成员、设置权限、管理订阅付款、转让和解散团队

**成员管理**：
- 团队所有者可设置团队管理员
- 团队角色：团队所有者、团队管理员、团队成员、游客
- 项目角色：管理员、编辑者、只读成员、禁止访问

**创建项目**：
- Apifox 项目对应一个 OpenAPI Spec
- 三种项目类型（不能混用）：
  - HTTP 项目：REST API、SOAP/WebService、GraphQL、WebSocket、SSE
  - gRPC 项目
  - Dubbo 项目
- 只有团队所有者和管理员才能创建项目

**项目初始配置**：
1. 项目语言（项目内容语言 vs 界面语言）
2. 默认响应模板
3. 响应组件
4. API 状态

**集成功能**：
- CI/CD 集成
- 数据库集成
- 消息通知集成（飞书、钉钉、企业微信、邮箱、Webhook）

### 4.2 GraphQL 调试

> 来源：https://docs.apifox.com/graphql.md

GraphQL 是一种用于 API 的查询语言，以及使用类型系统执行查询的服务器端运行时。

**新建 GraphQL 请求**：在项目中新建一个接口，依次点击 "Body -> GraphQL" 即可。

**调试 GraphQL**：在运行页面的 Query 框内输入查询语句。点击输入框的手动"获取 Schema"按钮可启用 Query 表达式的"代码补全"功能。

**常见问题**：
- 出现 `SyntaxError: Unexpected token } in JSON at position 214` 报错：通常是 JSON 格式不正确（多了/少了括号、逗号、字符串未正确关闭）。用在线 JSON 校验工具检查。

### 4.3 gRPC 调试

> 来源：https://docs.apifox.com/grpc.md

> ⚠️ Apifox 版本号需 ≥ 2.3.0 才能使用 gRPC 接口调试功能。

**新建 gRPC 项目**：点击 Apifox 首页的"新建项目"按钮，选择 "gRPC 项目（Beta）"。

**导入 Proto**：
- 首次导入支持 3 种方式：本地文件、托管 .proto 文件的 URL、服务器反射（Server Reflection）
- 目标 .proto 文件会被导入为 1 个 `Proto`，`service` 会被导入为服务，`rpc` 会被导入为方法
- 如果 .proto 文件依赖其他 .proto 文件，需要手动添加依赖关系目录
- 重新导入：右键点击 `Proto` → 重新导入

**调用方法**（支持 4 种类型）：
- Unary（一元调用）
- Server Streaming（服务端流）
- Client Streaming（客户端流）
- Bidirectional Streaming（双向流）

**ProtoBuf 与 JSON 数据类型映射**：

| ProtoBuf 3 | JSON | JSON 示例 |
| --- | --- | --- |
| message | object | `{"fooBar": v, "g": null, …}` |
| enum | string | `"FOO_BAR"` |
| map<K,V> | object | `{"k": v, …}` |
| repeated V | array | `[v, …]` |
| bool | boolean | `true, false` |
| string | string | `"Hello World!"` |
| bytes | base64 string | `"YWJjMTIzIT8kKiYoKSctPUB+"` |
| int32, fixed32, uint32 | number | `1, -10, 0` |
| int64, fixed64, uint64 | string | `"1", "-10"` |
| float, double | number | `1.1, -10.0, 0, "NaN", "Infinity"` |

**gRPC 与 Triple**：Triple 是兼容 gRPC 的 API 技术。URL 中的协议名 `tri://` 和 `grpc://` 是等价的。

## 5 设计 API

### 5.1 新建接口（详细可视化 OAS 设计）

> 来源：https://docs.apifox.com/create-an-api.md

建议遵循 OAS（OpenAPI 规范）来设计接口。

**清晰完整的接口应包含的要素**：
1. 接口路径
2. 请求方法
3. 接口描述信息
4. 请求参数
5. 返回响应和示例

**接口路径**：
- Apifox 推荐遵循 OAS 规范，接口里只需填写 Path，无需填写完整 URL
- "前置 URL"放到环境里，运行时自动拼接
- 推荐接口路径（Path）以 `/` 起始，更规范、更好支持 URL 模式 Mock

**请求方法**（9 种）：
1. GET：获取指定资源，通过 Query 参数传递
2. POST：提交数据进行处理，通常放在请求体中
3. PUT：完整更新或替换指定资源
4. DELETE：删除指定资源
5. OPTIONS：查询目标资源支持的 HTTP 方法
6. HEAD：与 GET 类似，但仅返回响应头
7. PATCH：部分更新指定资源
8. TRACE：返回服务器收到的请求
9. CONNECT：建立到服务器的隧道

**接口描述信息字段**：
- 命名：描述性名称
- 可见性：控制接口文档的可见性
- 状态：开发中、测试中、已发布等
- 责任人：项目成员
- 标签：关键词或短语
- **服务（前置 URL）**：默认为"继承自父级"
- OperationId：唯一标识符
- 说明：支持 Markdown

**请求参数**：
- Query 参数：在 URL 末尾以 `?` 开始
- Path 参数：用 **单大括号** 表示（如 `/pet/{petId}`），**不要**用 `:petId`
- Header 参数
- Body 参数

> ⚠️ **重要区分**：
> - `{parameter}`：单大括号表示 Path 参数，是 URL 路径中的占位符
> - `{{variable}}`：双大括号用于在请求中引用变量
> 
> 推荐的 URL 中使用变量写法：URL 保留占位符 `{}`，变量写在 Path 参数的"参数值"中（如 `{{petId}}`）

**返回响应**：
- HTTP 状态码：确定所有可能的状态码
- 数据格式：JSON、XML、HTML、Raw、Binary 等（**仅 JSON 和 XML 可配置数据结构**）
- 数据结构：详细描述返回的数据结构
- 示例：理想情况下应基于预定义请求

**添加响应组件**：对于通用错误响应（400、404、500），使用响应组件可复用预定义错误响应。

**添加响应示例**：点击"添加"，可添加多个示例，命名并提供响应数据。点击"自动生成"，Apifox 会根据数据结构定义自动生成合理的响应数据。

### 5.2 数据模型（Schema）

> 来源：https://docs.apifox.com/data-schemas.md

Schema 是 OpenAPI 规范的核心概念，也被称为"数据模型"，用于定义 API 中请求和响应的数据结构。Apifox 基于 JSON Schema 标准构建数据模型。

**数据模型的作用**：
- 统一数据结构：确保 API 一致性
- 生成 Mock 数据
- 自动生成文档
- 数据验证：验证 API 响应是否符合预期
- 模型复用：多个接口间共享

**新建数据模型**：
1. 手动创建：在"数据模型"目录下新建
2. 快速导入：支持从数据库表或 JSON Schema 中导入

**引用数据模型**：在接口的请求体、响应体或其他数据模型中直接引用。

### 5.3 接口历史记录

> 来源：https://docs.apifox.com/api-history.md

历史记录记录了团队成员对 API 各个字段所做的修改，以及由于"导入覆盖"产生的调整。

**功能**：
- 提供对比工具，在修改前后对版本进行对比
- 支持恢复到任意一个历史版本
- 要访问历史记录，点击 API 区域右上角的图标

**查看修订历史**：包括贡献者和时间戳信息。

**恢复版本**：点击 `还原此版本`，此操作会基于所选历史版本创建一个新版本，同时保留原始的修改历史。

## 6 调试 API

### 6.1 校验响应

> 来源：https://docs.apifox.com/validate-response.md

在 Apifox 中，发送接口请求后，系统会依据接口定义自动校验响应的结构是否符合预期。

**校验范围**：
- HTTP 状态码
- 返回内容的数据格式：JSON、XML、HTML、Raw、Binary、No-Content、MsgPack、Event-Stream
- 数据结构：只有 JSON 和 XML 能配置数据结构

**校验项**：

| 校验项 | 属性类型 | 示例 |
| --- | --- | --- |
| 必需属性 | All | $ 应该有必需属性 code |
| 值类型 | All | $.data.id 应当是 string 类型 |
| 非空键为空值 | All | $.data.id 应当是 string 类型 |
| 枚举值 | String, Integer, Number | $.data.status 应等于预定义值之一 |
| 数值范围 | Integer, Number | $.data.age 应大于等于 0 |
| 数值满足多重要求 | Integer, Number | $.data.quantity 应为 10 的倍数 |
| 字符串长度范围 | String | $.data.name 应不少于 3 个字符 |
| 字符串与接口定义 | String | $.data.name 应符合模式 "^[A-Za-z]" |
| 数组元素数量 | Array | $.data.tags 不应超过 2 项 |

**两类问题**：
- 服务器的响应不正确 → 后端需要修改
- 接口文档中的数据结构定义不正确 → 文档需要修改

**校验其他响应**：默认校验第一个响应（通常 200）。一个接口有多个响应时，可在校验区域右上角选择要校验的响应。

**响应校验设置**：
- "校验响应"开关默认开启
- 前往"项目设置 → 响应验证设置"调整
- 还可设置校验内容（HTTP 状态码、Header、Body）
- 如需对特定模块禁用校验，可在该模块中设置

**额外字段处理**：
- 默认允许额外字段存在
- 如要禁止：在 `object` 高级设置中，将"额外字段"配置为"禁止"
- 全局配置：项目设置 → 功能设置 → 响应验证设置 → 关闭 "Object 对象允许额外字段"

### 6.2 前后置操作

> 来源：https://docs.apifox.com/pre-post-processors.md、add-assertions.md、scripts.md

前置和后置操作是 Apifox 的关键功能。

**使用方法**：
1. 打开任意接口并切换到运行标签页（文档模式）或请求标签页（调试模式）
2. 切换到前置操作或后置操作部分，鼠标悬停在"添加操作"上，选择想要添加的操作
3. 填写添加操作所需的字段
4. 点击"发送"，请求将带着配置好的前置/后置操作执行
5. 文档模式下点击"保存为用例"；调试模式下点击"保存/保存为用例"

**前置操作可实现**：
- 设置请求参数和请求体的值
- 设置请求头（Content-Type、Accept、Authorization 等）
- 为请求添加认证
- 从数据库获取值作为请求参数
- 加密请求

**后置操作可实现**：
- 编写断言
- 从响应中提取变量
- 将数据写入数据库
- 可视化响应数据

**支持的操作类型**：
- **断言**（仅后置）：校验响应数据是否符合预期
- **提取变量**（仅后置）：用 JSONPath/XPath 提取值存储为变量
- **数据库操作**（前后置均可）：执行 SQL 查询
- **自定义脚本**（前后置均可）：JavaScript 代码
- **公共脚本**：可复用脚本片段
- **等待时间**（前后置均可）：模拟延迟

**执行层级**：可在 3 个层级配置
- 运行页/接口用例级别（默认）
- 接口级别
- 目录级别

**"变量替换 & 继承自父级"** 是特殊的前置操作，用于将 `{{variable}}` 替换为当前环境中定义的实际值。大多数前置操作会在变量替换之前执行。

**脚本语法**：Apifox 的脚本语法和 Postman 完全兼容，支持所有 `pm` 语法。

**调试**：用 `console.log("message")` 在控制台输出信息。

### 6.3 数据库操作

> 来源：https://docs.apifox.com/database.md

前置/后置操作支持添加数据库操作。

**使用步骤**：
1. 在运行标签页（文档模式）或请求标签页（调试模式）中，导航到后置操作
2. 鼠标光标悬停在"添加后置操作"上并选择"数据库操作"
3. 为数据库操作命名并设置数据库连接
4. 输入 SQL 命令（支持 `{{variables}}`）
5. 设置"提取结果到变量"（支持 JSONPath），可开启"控制台打印结果"开关
6. 点击发送请求，在控制台查看结果

> Apifox 支持标准 SQL 查询，但不支持存储过程这类复杂操作。

**支持的数据库**：
- 免费版：MySQL、SQL Server（≥2014）、Oracle、Db2、PostgreSQL、ClickHouse、MongoDB
- 付费版额外支持：达梦数据库、Redis

**配置数据库连接**：
1. 打开"项目设置 → 数据库连接"
2. 点击右上角"新建"创建连接
3. 选择数据库类型，填写连接信息（地址、端口、数据库名、用户名、密码）
4. 推荐使用变量填入（完全以变量形式填入的连接可保存在云端协同）
5. 也可通过 SSH 隧道建立更安全的连接

> ⚠️ 数据库的地址、端口、用户名、密码和数据库名**仅保存在本地**，不会同步到云端。成员之间无法共享，每位成员需手动配置。

**MySQL 使用提示**：最新的 mysql 模块对 MySQL 8 的 `caching_sha2_password` 加密方式支持不够完善。需用 `mysql_native_password` 模式修改 MySQL 账号密码：
```sql
ALTER USER 'username'@'%' IDENTIFIED WITH mysql_native_password BY '123456'
```

**在不同环境连接数据库**：为每个环境设置对应的数据库连接，切换环境时数据库查询会自动连接对应环境。

**在脚本中连接数据库**（使用 `pm.dataSource`）：
```js
var dbConfig = {
    type: 'mysql',
    host: '127.0.0.1',
    port: '3306',
    username: 'root',
    password: '123456',
    database: 'test',
}

pm.dataSource(dbConfig).query(
    `SELECT * FROM pets WHERE id = ${petId};`,
    (error, results) => {
        console.log('error', error);
        console.log('results', results);
        pm.test("查询结果验证", function () {
            pm.expect(results[0].name).to.eql("示例宠物名");
        });
        pm.environment.set('petName', results[0].name);
    }
);
```

**操作 NoSQL**：MongoDB 操作请参考 MongoDB 文档；Redis 操作请参考 Redis 文档。

**Apifox CLI 中使用数据库**：因为数据库操作是本地存储的，CLI 无法动态获取配置。需将数据库操作导出为配置文件，放在运行 CLI 的机器上。

## 7 测试 API

### 7.1 新建场景用例（自动化测试）

> 来源：https://docs.apifox.com/new-test-scenario.md

> 注：原"测试场景"已更名为"场景用例"。仅概念澄清，功能不受影响。

**新建场景用例**：
1. 在项目中点击左侧菜单栏中的"自动化测试"
2. 点击搜索栏右侧的 `+` 号按钮
3. 选择所归属的目录与设置优先级后完成创建
4. 可调整目录或给场景用例设置标签

**添加测试步骤**：测试步骤支持导入接口、接口用例、自定义请求和从 cURL 导入。

**从接口导入**（2 种同步模式）：
- **手动同步**：项目内"接口文档"发生数据变化时，测试步骤中的接口数据**不会自动更新**。点击"手动同步"按钮才会同步
- **自动同步**：项目内"接口文档"数据发生变化时，测试步骤中的接口数据**自动更新**

**从接口用例导入**（2 种模式）：
- **复制**：参数一并复制，与原项目内的接口用例数据**相互独立**。两者改动互不影响
- **引用**：直接使用原项目内的接口用例进行请求。**修改会双向同步**

**添加自定义请求**：可调用外部项目接口（如第三方支付接口），支持任意 HTTP 方法。

**从 cURL 导入**：将 cURL 命令一键导入到测试步骤中。

**流程控制条件**：支持分组、条件分支、ForEach 循环、For 循环和等待时间。

**从其它场景用例导入**：可复制其他场景用例的步骤或流程控制条件。

**引用其它场景用例**：可作为测试步骤引用其他场景用例。**不可引用当前场景用例本身**（防无限循环）。

**编排场景用例**：点击任意测试步骤进入编排模式。左侧显示整体流程，右侧显示选中步骤的详细信息。可用 ⬆️⬇️ 键快速切换步骤。**全部保存** 按钮可一次性保存所有步骤。

### 7.2 定时任务

> 来源：https://docs.apifox.com/scheduled-tasks.md

> ⚠️ 定时任务目前处于 Beta 阶段。运行定时任务需要先配置自托管 Runner。

**定时任务入口**：在自动化测试功能的目录树中，找到定时任务分类。所有定时任务以结构树形式展示。

**定时任务详情配置**：
- 任务名称、说明
- 启/停用
- 场景用例：可选择多个场景用例，每个都可独立配置"运行配置"
  - 运行环境、测试数据、循环次数、间隔停顿等
  - 环境/全局变量值：选择"使用远程值"或"导出本地值使用"
- 使用相同运行设置
- 运行周期
- 运行于（云端或自托管 Runner）
- 通知

**Runner 中的变量范围**：

| 范围 | 描述 | 适用 |
| --- | --- | --- |
| 当前场景用例 | 当前场景用例对应一个文件，仅该场景可读写 | 最小范围，影响面最小 |
| 当前定时任务 | 当前定时任务对应一个文件，定时任务内所有场景可读写 | 中等范围（推荐） |
| 当前定时任务目录 | 当前定时任务目录对应一个文件，目录内所有定时任务所有场景可读写 | 最大范围，影响面最大 |

**运行结果**：在客户端"定时任务 - 运行历史"中查看。建议开启通知。

### 7.3 性能测试

> 来源：https://docs.apifox.com/performance-testing.md

> 性能测试功能处于 Beta 阶段。

**运行前配置**：
- **运行环境**：场景用例中的运行环境继承自当前项目中的环境
- **测试数据**：可选择「随机匹配」或「顺序匹配」模式
  - 随机匹配：每个虚拟用户随机选择一行数据
  - 顺序匹配：按顺序选择；如虚拟用户数 > 测试数据行数，超出部分的虚拟用户不会运行

**三个可调测试项**：
- **虚拟用户数（并发用户数）**：最高支持 100 个
- **运行时间**：执行的总时长，每个虚拟用户一直循环执行全部接口
- **爬坡时间**：在指定时间内线性逐步添加并行用户

**运行性能测试**：触发后会展示可视化面板，显示各接口的总请求数、每秒接口请求数、平均响应时间、最大/最小响应时间、请求失败率等。

> 单位时间内，一个项目只能运行一个性能测试。

**检视测试过程**：将鼠标移至测试图表实时查看。点击"请求失败率"检查失败请求。

> 性能测试只记录错误请求分类，不会记录详细错误信息和每个接口请求详情。如有预期之外的错误，先运行"功能测试"。

**查看测试报告**：点击"测试报告" tab 查看历史报告。

## 8 Mock API

### 8.1 智能 Mock

> 来源：https://docs.apifox.com/smart-mock.md

智能 Mock 支持根据接口文档直接生成 Mock 数据，无需额外配置。

**数据来源**（3 个）：
1. 属性名称中对应的 Mock 表达式
2. 响应定义中属性的 Mock 字段
3. 响应定义中的 JSON Schema

**根据名称自动生成**：智能 Mock 的核心算法根据属性的类型和名称自动匹配相应的 Mock 数据。内置规则通过通配符或正则表达式匹配名称字符串。

可在"项目设置 → 通用设置 → 功能设置 → Mock 设置"中查看内置规则。如不满足需求，可创建自定义匹配规则。

**根据 Mock 字段生成**：如果响应定义中某个属性的 Mock 字段有值，会覆盖通过名称生成的值。可直接填写固定值，或写入动态值表达式。

**根据 JSON Schema 生成**：生成的 Mock 数据会受 JSON Schema 约束：
- 字符串长度限制（"name" 生成 "Richard"，但限制 3-5 字符时变 "Richa"）
- 枚举值限制
- 数值范围
- 数组元素数量范围

### 8.2 云端 Mock

> 来源：https://docs.apifox.com/cloud-mock.md

**特点**：
- 全项目成员可访问
- 持续可用，不受项目成员电脑开关机状态影响
- 适合公开 API 文档
- 为非生产环境提供可靠数据来源

**开启**：
1. 项目设置 → 功能设置 → Mock 设置
2. 启用"云端 Mock"

**使用**：
1. 访问任一接口，在 Mock 标签页的"Mock 地址"中点击"云端"标签
2. 点击"快捷请求"立即获取响应数据
3. GET 请求可直接在浏览器访问云端 Mock 地址

**访问权限**（Token 鉴权）：
- 项目设置 → 功能设置 → Mock 设置 → 设置"Token 鉴权"
- URL 中加 token：`?apifoxToken=xxx`
- 快捷请求在 Header 添加 `apifoxToken`
- form-data 和 x-www-form-urlencoded 在 Body 添加 `apifoxToken`

### 8.3 自定义 Mock（Mock 期望）

> 来源：https://docs.apifox.com/custom-mock.md

**两种主要方式**自定义 Mock 数据：

**方式一：自定义特定字段**

1. **直接输入值**：在接口定义的 Mock 字段中指定固定值，其他字段使用智能 Mock
2. **使用 Faker.js 动态值**：语法 `{{$分类.方法}}`
   - `{{$person.fullName}}` → `李明`
   - `{{$internet.email}}` → `wang.ming@163.com`
   - `{{$commerce.productName}}` → `高品质塑料自行车`
3. **使用带参数的 Faker 方法**：
   - `{{$number.int(min=0,max=10000)}}`
   - `{{$phone.number(style='human')}}`
   - `{{$number.int(multipleOf=3)}}`
   - `{{$helpers.arrayElement(['红色','蓝色','绿色'])}}`
   - `{{$date.between(from='2024-01-01',to='2024-12-31',format='yyyy-MM-dd')}}`
4. **连接多个动态表达式**：
   ```
   {{$location.streetAddress}}，{{$location.city}}，{{$location.state}}，{{$location.zipCode}}，{{$location.country}}
   ```

**方式二：自定义整个 Mock 响应（Mock 期望）**

**返回指定数据**：添加无参数条件的期望，返回固定数据。

**返回条件数据**：根据不同请求参数返回不同 Mock 数据。
- Mock 引擎根据请求参数匹配条件，按从上到下顺序返回第一个匹配的期望
- 没有匹配时，按"项目设置 → 功能设置 → Mock 设置"中定义的 Mock 优先级返回
- 条件支持 query、path、header、cookie、body 参数
- 设置多个条件时取交集
- body 参数支持 JSONPath
- body 参数仅支持 JSON，不支持 XML
- 参数条件**不支持** `{{变量}}`
- 可添加 IP 条件

**返回动态 Mock 数据**：使用 Faker.js 和 Nunjucks 语法：
```json
{
    "data": [
        {% for i in range(0, 20) %}
        {% if i>1 %},{% endif %}
        {
            "id": {{i}},
            "firstname": "{{$person.firstName}}",
            "lastname": "{{$person.lastName}}"
        }
        {% endfor %}
    ],
    "success": true
}
```

> `{{$...}}` 是 Apifox 改写的 Faker.js 语法（原生是 `faker.person.firstName()`）
> `{% for ... %}` 来自 Nunjucks
> `{{i}}` 不是 Apifox 变量，而是 Nunjucks 变量。**Mock 期望中不能使用 Apifox 变量**

**更多功能**：
- 自定义 Headers
- 配置 HTTP 状态码
- 响应延迟
- 控制每个期望值在本地 Mock 和云端 Mock 环境中的启用状态

## 10 迭代分支

### 10.1 新建迭代分支

> 来源：https://docs.apifox.com/create-sprint-branch.md

**创建入口**：
- 目录树顶端右上角的迭代分支切换功能中点击"创建迭代分支"
- 也可在「项目设置 → 管理迭代分支」中创建

**适用场景**：
- 进入新迭代，需求明确，需进入技术设计流程时

### 10.2 在迭代分支中测试 API

> 来源：https://docs.apifox.com/test-api-in-sprint-branch.md

新建迭代分支中，自动化测试功能默认没有内容。

**从主分支导入测试场景**：支持从主分支导入测试场景。导入时会自动选中主分支中已包含该接口的测试场景，方便测试人员筛选导入。

> 导入的测试场景会自动将其所有父级目录一并导入。在目录树上可看到关联标识。

**新建测试场景**：基于迭代需求，特别是新增接口时，可能需要建立新测试场景。

**编排迭代分支测试场景**：与主分支测试场景一样。在迭代分支的测试场景内编排时，UI 上会通过明显区别标记是使用当前迭代分支内的资源还是主分支的资源。

**运行测试场景**：迭代分支的测试场景运行规则也与主分支一致。如果步骤关联迭代分支中的资源，则使用迭代分支数据；如果关联主分支资源，则使用主分支数据。

### 10.3 合并迭代分支

> 来源：https://docs.apifox.com/merge-sprint-branch.md

在迭代分支内完成 API 定义开发并成功上线后，可将分支内的部分/所有接口变更合并至主分支。

**合并入口**：
- 接口管理中：分支选择器内的"合并"按钮，或目录树下方的"合并到主分支"按钮
- 自动化测试中：鼠标 hover 在测试场景的 `...` 按钮上 → "合并到主分支"

**合并入非受保护分支**：
- **待合并内容总览**：
  - 筛选器：可查看修改的资源或所有资源
  - 接口管理目录树：展示合并后主分支目录树的最终效果
  - 资源颜色标记：灰色（未改动）、橙色（修改）、绿色（新增）
  - 可勾选/取消勾选决定合并哪些资源
  - 合并后接口状态：跟随当前迭代分支/跟随主分支/指定状态

- **资源类型**：
  - **新增资源**：当前迭代分支中创建，主分支上没有
  - **修改资源**：从主分支上导入，有关联关系
  - **无变动资源**：导入但未修改，不可选择合入（也没必要）

> ⚠️ 如果不选择合并某个父级资源，则其下方所有子级资源**不能**单独合入主分支。

- **合并后**：toast 提示操作成功，打开合并完成总结弹窗
- **撤销合并**：在主分支中点击资源的"历史记录"，可看到合并操作修改内容并可回滚

**合并入受保护分支**：
- 需要创建合并请求，由项目管理员审核后合入
- **创建合并请求**：在"合并"后选择需要合并的资源 → 点击"创建合并请求"
- **审核合并请求**：项目概览 → 合并请求页 → 审核 → 接受/拒绝
- **修改已提交的合并请求**：修改分支中的内容，合并请求中的内容会自动同步
- **拒绝合并请求**：状态标记为"已关闭"

**自动化测试场景的合并**：
- 测试场景的合并**与接口管理内容的合并互相独立**
- 测试场景的合并需要**逐个**资源合并
- ⚠️ 警告：请先合并接口管理中的资源，再合并测试场景
- 对已设置保护的分支，测试场景合并**仅项目管理员**可执行

## 11 团队与项目

### 11.1 团队与项目（管理中心）

> 来源：https://docs.apifox.com/management-center.md

Apifox 将工作空间划分为 **项目**、**团队** 和 **组织** 三个层级。

**项目**（最小）：
- 设计、测试和管理 API 及其文档的核心工作空间
- 在项目中创建、编辑和测试 API
- 多个项目可对 API 和文档进行分类

**团队**（中间）：
- 管理和成员的基本协作单元
- 可隶属于某个组织，也可作为独立工作空间
- 功能：隔离数据、控制访问、安全协作

**组织**（最大，可选）：
- 适合需要集中管理多个团队的企业
- 集中管理、统一权限、确保合规
- 规模较小的协作团队可直接使用独立团队

**如何选择**：
- 团队不大、业务集中：只用一个团队
- 规模大、业务分散：先建组织，再在组织里按业务划分多个团队

**邀请成员入口**对比：

| 对比项 | 项目级邀请 | 团队级邀请 | 组织级邀请 |
| --- | --- | --- | --- |
| 邀请入口 | 项目 → 项目设置 → 成员 | 主窗口 → 成员/权限 → 邀请 | 组织管理后台 → 成员页面 |
| 适用目的 | 邀请协作者参与指定项目 | 加入某一团队，配置团队角色和项目权限 | 由 HR/IT 管理员集中维护组织成员 |
| 典型场景 | 跨部门协作或外包 | 创建新业务线或部门 | 新员工入职或跨团队调配 |
| 邀请后 | 加入当前项目，团队内其他项目为"禁止访问" | 加入当前团队，可设团队角色和项目角色 | 成为组织成员，按需分配到团队 |

### 11.3 单点登录（SSO）

> 来源：https://docs.apifox.com/sso.md

> Apifox 商业旗舰版可使用单点登录（SSO）功能。

**使用前提**：
- 身份提供商（IdP）必须支持 SAML 2.0 协议
- 已经在 Apifox 内创建了组织
- 该组织已购买商业旗舰版

**企业使用单点登录的优点**：
- 优化用户体验：只需记住一个用户名和密码
- 提高工作效率：快速、无缝地访问必要资源
- 提升安全性：降低密码疲劳、集中管理安全策略
- 简化账户管理：仅需在一个地方管理用户账号
- 降低 IT 支持成本：减少密码重置请求

## 12 Apifox CLI

### 12.1 安装和运行 CLI

> 来源：https://docs.apifox.com/install-and-run-cli.md

Apifox CLI 是基于 Node.js 开发的命令行工具，可用于本地终端、CI/CD 平台或 AI Agent。

**前置要求**：
- 安装 Node.js（要求 ≥ v16）
- 建议在系统上全局安装

**安装命令**：

国内镜像源：
```bash
npm i -g apifox-cli@latest --registry=https://registry.npmmirror.com/
```

npm 源命令：
```bash
npm install -g apifox-cli
```

**验证安装**：
- macOS / Linux：`node -v && apifox -v && which node && which npm && which apifox`
- Windows（在 cmd 中运行，不要在 PowerShell 中）：`node -v && apifox -v && where node && where npm && where apifox`

> ⚠️ PowerShell 运行 Apifox CLI 命令报错 `apifox: could not find "html cli" reporter`：PowerShell 不支持 `html,cli` 这个传参，可加引号 `'html,cli'`，如 `apifox run --access-token APS-xxx -t xx -e xx -n 1 -r 'html,cli'`

**Linux 安装后无法直接使用**：需要创建符号链接：
```bash
ln -s /home/bjz/node-v22.14.0-linux-x64/bin/apifox /usr/local/bin/apifox
```

**更新**：
```bash
npm install apifox-cli@latest -g
```

**登录账号**：
```bash
apifox auth login
```

## 13 响应组件 / 变量 / 模块 / 脚本 等核心机制

### 13.1 响应组件

> 来源：https://docs.apifox.com/response-components.md

成功的 200 OK 响应因不同接口而异，但 400、404 等错误响应往往一致。Apifox 提供"响应组件"功能来重复使用预定义的错误响应。

> Apifox 的响应组件与 OAS 规范中的组件兼容。

**添加响应组件**：
- 接口管理 → 目录树 → 组件库 → 响应组件 → 新建响应
- 创建响应组件类似于定义 API 的响应部分（HTTP 状态码、内容格式、响应数据结构、示例）
- **新增接口时默认添加**：如选择"是"，该组件将默认添加到所有新创建的接口中（已存在的接口不受影响）

**引用响应组件**：
- 在接口的"响应"部分引用预定义组件
- 引用的响应组件**无法在接口内修改**
- 必须解绑后才能修改
- 一个接口内同一组件只能引用一次

**批量操作**：可批量将已存在的响应组件 `添加` 到选定的接口，或批量从选定接口中 `移除`。

**默认响应模板**：
- 团队标准化响应结构的模板
- 创建新接口时，该模板作为初始响应
- 仅存在一个，无法添加或删除
- 初始是 200 成功响应，Content-Type JSON，结构为空 Object 节点

**常见问题**：
- 可以把响应组件作为默认响应吗？**不可以**。响应组件用于通用错误响应（400、404）。如需固定的默认响应，请使用"默认响应模板"。

### 13.2 全局/环境/模块/临时变量

> 来源：https://docs.apifox.com/global-environment-session-variables.md

**变量类型与优先级**（高 → 低）：
**临时 > 测试数据 > 环境 > 模块 > 项目全局 > 团队全局**

> Apifox 中变量以字符串形式存储。对象/数组需用 `JSON.stringify()` 转换，读取时用 `JSON.parse()` 解析。

**全局变量**（两种类型）：
- 项目中共享的全局变量
- 团队中共享的全局变量（跨项目）

> 1. 在项目环境管理页面，仅能查看已有的团队全局变量、修改本地值
> 2. 通过前后置操作设置团队全局变量仅能修改本地值
> 3. 添加/删除/修改变量名和远程值需团队管理员在"团队资源 → 团队变量"中操作

**模块变量**：Postman 导入的 Collection 变量需要导入到模块变量中。

**环境变量**：使你能根据特定环境（本地开发、测试、生产）调整工作配置。每次只能激活一个环境。

**测试数据变量**：来源于外部 CSV 或 JSON 文件，用于数据驱动测试。仅在测试运行期间有效。

**临时变量**：仅在单个接口或测试场景的运行期间有效，运行结束后消失。

**远程值和本地值**：
- **远程值**：保存在 Apifox 服务器，与团队成员同步
- **本地值**：仅保存在本地设备，不与服务器同步
- 本地值为空时使用远程值；设置本地值后优先使用本地值
- 更换设备时本地值不会迁移，可通过导出/导入环境迁移
- Apifox Web 版的本地值存储在浏览器数据中

> CLI 中运行时使用变量的远程值，客户端运行时使用本地值——这可能导致结果不同。

**设置变量方法**：
1. 在"环境管理"中设置
2. 通过"提取变量"设置（从响应中提取）
3. 在"脚本"中设置
4. 将"数据库数据"设置为变量

**使用变量 `{{}}`**：
- 在 URL、参数、请求头、认证设置、请求体等地方使用
- 字符串类型需要双引号：`"name": "{{CurrentStatus}}"`
- 其他类型不加双引号：`"quantity": {{TotalPet}}`
- 双大括号有时触发 JSON 格式错误警告但可忽略

**读取变量的子元素值**：
- 对象变量：`{{user.name}}` 或 `{{user[0].name}}`
- 数组变量：`{{user[0].name}}` 或 `pm.variables.get("user[0].name")`

**变量场景**：
- **可用**：接口、前置/后置脚本、测试场景
- **不可用**：接口文档（默认值、Mock 数据）、Mock（高级 Mock、Mock 脚本）

> 不要将一个变量的值设置为另一个变量。

### 13.3 模块

> 来源：https://docs.apifox.com/module.md

模块用于对项目中的接口进行组织。模块与"服务"概念类似。

**适用场景**：
- 关联性较强（如 AI 项目：文本模型 API、文生图模型 API、语音模型 API）
- 微服务（电商：鉴权服务、订单服务、商品服务）
- 多版本（Legacy、LTS、Latest）

**创建模块**：
1. 将鼠标悬停在目录树上方的 `+` 按钮
2. 选择"新建模块"入口
3. 输入模块名称后保存
4. 模块详情：资源统计、用例/场景覆盖统计、导出入口、数据源设置、模块变量

**维护模块对应的前置 URL**：在"环境管理"中，前置 URL 部分会自动增加新创建的模块。每个环境中的每个模块都有独立的前置 URL。

**请求时正确使用前置 URL**：
- 某模块中的接口，实际请求时会取到该模块在当前环境下的前置 URL
- **不可以**让当前模块的接口使用其他模块的前置 URL

> ⚠️ 不推荐单个模块中存在多服务。2.7.16 版本后建议将一个模块内的多服务拆成多个模块。

### 13.4 使用脚本（前置/后置）

> 来源：https://docs.apifox.com/scripts.md

Apifox 内置了基于 JavaScript 的脚本引擎。

**可实现的功能**：
1. 校验接口返回结果是否正确（后置脚本）
2. 动态修改接口请求参数，如添加签名参数等（前置脚本）
3. 在不同接口之间传递数据（通过脚本操作变量）
4. 调用其它编程语言编写的程序（Java .jar、Python、PHP、JS、BeanShell、Go、Shell、Ruby、Lua 等）

> Apifox 的脚本语法和 Postman 完全兼容。

**使用阶段**：
1. 发送接口请求到服务器之前（前置脚本）
2. 收到响应之后（后置脚本）

**调试**：用 `console.log("message")` 在控制台输出。

**常见问题**：
- Apifox 支持 `pm.nextRequest()` 吗？**不支持**。Apifox 不支持"运行集合"功能，但可在自动化测试模块中创建测试场景，添加 if 条件，根据不同条件发送不同请求。

### 13.5 断言

> 来源：https://docs.apifox.com/assertions.md

断言用于校验接口请求的响应是否符合预期。

**在后置操作里添加断言**：
1. 找到后置操作
2. 鼠标悬停在"添加后置操作"上，选择"断言"
3. 选择断言对象（响应头、响应正文、状态码）
4. JSON 正文用 JSONPath 提取
5. 设置断言条件（等于、不等于、包含、大于、小于等）
6. 点击发送

> ⚠️ Apifox 中执行断言时，所有数据都会自动转换为字符串进行比较。可能导致 `4` 不等于 `4.0`。需要更精确控制可使用自定义脚本。

**基于实际响应设置断言**：直接在返回响应中 hover 某个响应字段，点击右边的"设置断言" icon 即可。

**用脚本做断言**：使用 `pm.test` 语法。Apifox 兼容 Postman 脚本。

### 13.6 提取变量

> 来源：https://docs.apifox.com/extract-variables.md

Apifox 支持从接口响应中可视化提取值并保存为变量。

**提取步骤**：
1. 导航到后置操作
2. 悬停在"添加后置操作"上并选择"提取变量"
3. 输入变量名并选择变量类型
4. 选择提取来源（响应 JSON、XML、文本、头、cookie、耗时）
5. JSON/XML 用 JSONPath/XPath 解析

**从实际响应中提取**：hover 响应字段 → 点击"提取变量"。

**JSONPath 提取工具**：点击 JSONPath 输入框右侧的箭头图标。左侧显示 JSON 响应，右上方的 JSONPath 表达式框中输入表达式，下方结果区域动态提取。

> 如果 JSONPath 表达式包含通配符 `*` 等可能提取多个值的元素，结果会以数组形式返回。开启"继续提取"选项可指定索引值直接获取目标值。

### 13.7 接口调试用例

> 来源：https://docs.apifox.com/api-test-cases.md

不同于 Postman，Apifox 分为"接口"和"接口调试用例"，一个接口有多个调试用例。当接口里的 URL 或参数更改后，会自动同步修改所有调试用例。

**创建接口调试用例**：在接口的"运行"标签页中发送请求或调试后，点击 `保存为用例`。

**调试用例存储的数据**：
- 请求参数值（Path、Query、Header、form-data Body）
- 请求体内容（RAW、JSON、XML 等）
- 接口的前后置操作
- 接收到的响应数据
- 响应校验设置

**最佳实践**：
1. 确定 API 定义的数据结构
2. 为每个接口创建多个调试用例，覆盖不同条件
3. 为每个调试用例编写断言或发送请求前后的处理脚本
4. 在接口测试用例中复制调试用例，或直接转化为测试用例
5. 在自动化测试中引用接口调试用例
6. API 定义更新时可同步：调试用例全部自动同步；测试用例可手动更新；测试场景步骤可设置自动/手动同步

# 第二部分 常见问题（https://docs.apifox.com/5835927m0）

> 共 11 个分类，约 100+ 个 FAQ 条目。

## 1 导入/导出

### 如何导入接口数据到 Apifox?

1. 进入"项目设置 → 导入数据"面板
2. 选择需要导入的数据格式
3. 按指引填写必要信息，点击"继续"
4. 预览数据并确认导入选项
5. 完成导入

### 如何导入 cURL 到 Apifox？

1. 鼠标移到左侧搜索框旁边的 `+` 号，在下拉列表里点击"导入 cURL 数据"（快捷键 `Ctrl(⌘) + I`）
2. 在打开的窗口中，粘贴 cURL 格式数据
3. 点击"确定"，看到数据复制到"快捷请求"界面
4. 可将"快捷请求"保存为接口
5. 也可把 cURL 命令直接粘贴到地址栏，Apifox 会自动解析

### 如何将 Postman 的环境变量迁移到 Apifox？

- Postman 中用 `{{baseUrl}}` 指定前置 URL，迁移到 Apifox 时自动转为环境管理中的"服务"
- Postman 变量分 3 种：集合变量、环境变量、全局变量
- **集合变量**：随 JSON 文件一起导出，导入 Apifox 时自动转为全局变量
- **全局/环境变量**：不会包含在导出的 JSON 文件中，需单独导出
- 导出 Postman 全局变量：Environments → Globals → Export
- 导出 Postman 环境变量：Environments → 环境名称右侧的三个小点 → Export
- 导入到 Apifox：项目设置 → 导入数据 → Postman → 上传文件
- ⚠️ 导入的只是变量，「前置 URL」还需要手动在环境管理中添加

### 为什么导出的 API 数量减少了？

多个 API 使用相同的方法和路径时可能发生。HTML 和 Markdown 是通过 OpenAPI 数据转换导出的，OpenAPI 规范不支持多个 API 共享相同的方法和路径。

### 为什么导出到 Markdown 和 HTML 时 API 顺序混乱？

OpenAPI 中的 Swagger 规范对 API 的排序或分组没有明确支持。要获得有序的导出，建议使用 Apifox 的原生格式。

### 如何将文档导出为 PDF/Word？

Apifox 不支持直接导出为 PDF 或 Word 格式，可先导出为 Markdown，再用外部工具转换（Typora、MarkText、VSCode 插件）。

### 如何在 Apifox 中导入 Swagger/OpenAPI 时自动将接口分组？

- 接口的目录会基于 tags 定义导入
- 系统将 tags 数组的第一个值设置为该接口的目录
- tags 值中存在斜杠 `/` 时，用作分隔符区分父子目录
- 如 tags = `["Orders/User Orders/Sub Folder"]`，导入后位于 Orders → User Orders → Sub Folder
- 如希望目录与导入源完全相同，需开启"更新接口所在目录"开关

### Postman 导入提示错误：URImalformed

文件里的某条数据的 path 不符合规范，带有 `%` 之类的特殊字符，请检查。

### 开放接口导入「OpenAPI/Swagger 格式数据 - URL 导入」，使用本地服务地址无法导入

原因：开放接口导入在 Apifox 服务端执行，URL 必须是外网可访问。
解决：1. 切换到字符串方式导入；2. 文件传到 GitHub 公开库后用 URL 导入。

### 导入报错，如何排查？

1. 确认按帮助文档操作
2. 确认在客户端导入，更新版本
3. 在 Web 端测试
4. 看前端报错（Win: alt+7+8，Mac: option+cmd+i）
5. URL 导入排查：浏览器打开链接测试
6. 文件上传导入排查：用 https://editor.swagger.io/ 在线校验

## 2 发送请求

### Apifox 是否支持调试 Socket.IO？

支持。详见帮助文档。

### Apifox 是否支持在 WebSocket 接口中使用前置/后置脚本或者断言？

目前不支持，后续版本考虑加入。

### 为什么发送请求出现 "socket hang up"？

连接中断，Apifox 没收到响应或响应不完整。原因：
1. 接口服务端问题（宕机、过载、配置错误、开发环境代码断点）
2. 客户端超时配置问题
3. 客户端网络代理问题
4. 响应数据过大（可启用 gzip 压缩）

排查：尝试请求 `https://echo.apifox.com/get`。

### 为什么发送请求，提示 "Invalid URI xxx"？

1. 检查接口是否指定到前置 URL 为空的服务
2. 检查前置 URL 是否设置为变量，确认变量已设置
3. 提供版本号、接口服务设置、环境设置给技术支持

### 为什么同一个接口客户端请求成功，web 端调试出现 "无法请求地址"？

原因：
1. 浏览器证书问题（HTTPS 重定向到 443 端口，浏览器无法忽略证书错误）
2. 网络或防火墙限制

解决：
1. 检查网络连接
2. 浏览器证书管理（添加信任或使用 HTTP）

### 接口响应过大时报错提示超出 Node.js 字符串最大长度？

Node.js V8 引擎对单个字符串长度限制在 337MB 左右。响应超过此限制时可能内存不足或字符串处理错误。

### 为什么在路径中不支持输入 "#"？

URL 中的 `#`（哈希符）属于片段标识符，HTTP 协议规定 `#` 及其后的内容不会被发送到服务器。建议用 `%23`（URL 编码的 `#`）代替。

### 如果一个字符串属性有多个枚举值，怎么保证在整个文档里都保持一致？

将该属性定义成单独的数据模型，根节点设置好数据类型和枚举值，在不同地方引用。

### 数组如何配置枚举？

**场景一：字符串数组，每个元素是固定值**
```json
{
  "type": "array",
  "items": {
    "type": "string",
    "enum": ["A", "B", "C"]
  }
}
```
- 开启"所有元素必须唯一"避免重复值

**场景二：限制整个数组的取值是固定的几种（仅在 JSON Schema 中支持）**
```json
{
  "type": "array",
  "enum": [[1, 2], [3, 4]]
}
```

### 数组如何设置元素的唯一性？

数组-高级设置里有`所有元素必须唯一`的设置。

### form-data 中字段使用 JSON 值

1. 字段类型设置为 `string`
2. 设置 Content-Type 为 `application/json`

### 为什么在 Header 添加 Authorization 会有删除线？

配置了多个 Authorization（接口、目录、根目录的 Auth）。需要检查是否重复设置。

### 如何查看最近创建 / 修改的接口？

**方法一**：左侧接口根目录 → 全部接口 → 表头设置开启"创建时间"、"修改时间"列，可按表头排序。

**方法二**：开启变更通知提醒（站内信、邮件）。

### 如何在 Apifox 中的同一字段处理字符串和文件类型？

通过字段-数据类型右侧的"高级设置"按钮，选择 JSON Schema：
```json

    "oneOf": [
        {"type": "string", "format": "uri"},
        {"type": "string", "format": "binary"}
    ]
}
```

大概率是项目内响应组件数量过多导致。优化：
- **方案一**：用数据模型复用相同响应结构
- **方案二**：用组合模式（oneOf）合并相似响应组件

### 如果同时发送 file 和 json（body 请求参数又要有实体类又要有文件）

1. Body 选择 `form-data`，选择 `file` 类型上传文件
2. 实体类字段设置 `content-type` 为 `application/json`

### 接口参数值如何设置为 null

使用 `{{变量名|default('null', true)}}`：
- 变量有值：发送实际值（如 `"Tom"`）
- 变量为空：发送 `null`

因为 Apifox 支持"模块"功能，建议为每个服务分别创建一个模块，在"环境管理"中配置对应前置 URL。原目录结构也可直接转成模块。

### JSONPath 只能提取数组，那在 Apifox 里怎么从数组中提取单个元素呢？

### 使用 Windows 版本连接 DB2 数据库时报错怎么解决？

2. 新建 LIB 变量，值为 `<Apifox 安装位置>\resources\app.asar.unpacked\node_modules\ibm_db\installer\clidriver\lib`

### 发送请求失败 "Error: getaddrinfo ENOTFOUND xxx.xxx.xxx.xxx" 的原因及排查方法

通常表示无法解析请求中的域名或主机名或网络不可达：
1. URL 或 IP 地址错误
2. DNS 解析失败（`nslookup`、`dig` 测试）
3. 网络连接问题（`ping`、`telnet`）
4. 本地网络环境问题（VPN/代理/防火墙）
5. Apifox 配置问题（URL 协议/端口、Host 头、SSL 验证）
6. 本地环境问题（重启路由器/换网络）

### 为什么 Web 端发送请求正常，客户端发送请求，出现 "read ECONNRESET"？

1. Apifox 版本问题（升级）
2. Apifox 配置问题（超时时间、SSL 验证）
3. 防火墙或代理问题
4. 网络不稳定
5. 服务器负载过高
6. 服务器配置问题（请求头不一致）

### 使用 Apifox 连接 Oracle 数据库报错 NJS-045？

Oracle 官方在 ARM64 架构上存在兼容性问题，OracleDB Db2 不支持 arm64。

### 怎么把其它工具的环境迁移到 Apifox？

### 为什么 WebSocket 在 web 端连接正常，在客户端报 "1006 Abnormal Closure"？

- WebSocket 接口可访问外网：尝试切换网络（手机热点）
- 手机热点正常：检查是否开启代理
- 手机热点也报错：手动将浏览器中请求 WebSocket 接口时携带的头信息复制到 Apifox 客户端

### 为什么网络正常，访问 Apifox 提示 "连接 Apifox 服务器出错"？

**情况一：本地网络、VPN 代理或防火墙拦截（最常见）**
1. 检查 Apifox 网络代理设置
2. 浏览器访问 `apifox.com` 是否正常
3. 尝试更换网络
4. 检查控制台报错（Windows: `alt+7+8`，macOS: `option+cmd+i`）
5. 将 `*.apifox.com` 和 `*.apifox.cn` 添加到白名单
6. 提供 IP 地址（https://ip138.com/）给技术支持

**情况二：系统缺少 SSL 根证书（老旧系统）**
- 下载 Sectigo Root Certificates
- 双击 .crt 文件 → 安装证书 → 本地计算机 → 受信任的根证书颁发机构
- 重启 Apifox 客户端或浏览器

### 为什么 curl 请求正常返回 200，但在 Apifox 中请求却返回 400？

- 检查请求头：Host 头缺失通常导致 400
- 大小写：仔细对比请求头
- 请求体：确认内容和格式一致
- 认证信息：API Key、Bearer Token 等

### 为什么在 Apifox 上传文件，后台接收不到？

1. 发送文件到 `https://echo.apifox.com/post` 验证
2. 检查服务器端代码
3. 确认 Content-Type 为 `multipart/form-data`
4. 检查网络连接

Apifox 目前兼容 2.7.x 和 3.x 版本的 Dubbo。检查：
1. Dubbo 服务端是否使用 Dubbo 协议 + Hessian 序列化
2. 网络连通性（telnet）
3. 服务可用性

4. 点击"加载已解压的扩展程序"

### 接口签名使用 AES-GCM 加密

内置的 crypto-js 不支持 AES-GCM，使用 jscrypto：
```js
fox.liveRequire("jscrypto", (JsCrypto) => {
  try {
    var key = JsCrypto.Hex.parse("...");
    var msg = JsCrypto.Hex.parse("...");
    var iv = JsCrypto.Hex.parse("...");
    var authData = JsCrypto.Utf8.parse("some plain text data for authentication. This will not be encrypted.");
    var encryptedData = JsCrypto.AES.encrypt(msg, key, { iv, mode: JsCrypto.mode.GCM, authData });
    var cipherText = encryptedData.cipherText;
    console.log(cipherText)
  } catch (error) {
    console.error("An error occurred during liveRequire callback", error);
    throw error;
  }
});
```

### 前置脚本如何使用 SHA256withRSA 加密？

使用 jsrsasign 库：
```js
const rsa = require("jsrsasign");
var privateKeyPEM = `...`; // PEM 格式私钥
var sig = new rsa.KJUR.crypto.Signature({ alg: "SHA256withRSA" });
sig.init(privateKeyPEM);
sig.updateString("hello world");
var signatureValue = sig.sign();
console.log(signatureValue);
```

### Web 端运行接口时提示 "dial tcp [::1]:3000: connect: connection refused"？

解决方案：安装浏览器扩展。

### 为什么使用 Web 网页端，通过浏览器插件请求 Ollama 部署的大模型会提示 403？

Chrome 插件发送的请求携带 `origin: chrome-extension://xxx`，Ollama 不支持。
解决：修改 Ollama 配置以放行 chrome-extension 来源的请求。

### 为什么在 WEB 端中修改 Referer 请求头无效？

Referer 属于浏览器的"禁止修改的请求头"，受浏览器安全策略限制。
**建议使用客户端**。

浏览器禁止修改的请求头列表（含但不限于）：
Accept-Charset, Accept-Encoding, Access-Control-Request-Headers, Access-Control-Request-Method, Connection, Content-Length, Cookie, Date, DNT, Expect, Host, Keep-Alive, Origin, Permissions-Policy, Proxy-*, Sec-*, Referer, TE, Trailer, Transfer-Encoding, Upgrade, Via 等。

### 接口返回的是 Protobuf 数据，如何正常查看？

通过后置脚本结合 `protobufjs` 库解析：
```js
fox.liveRequire({
    name: "protobufjs",
    version: "8.6.2"
}, (protobuf) => {
  const proto = `...`;
  const stream = pm.response.stream;
  const root = protobuf.parse(proto).root
  const TestMessage = root.lookupType("TestMessage")
  const json = TestMessage.decode([...stream])
  pm.response.setBody(json);
});
```

### 接口请求中 Header 携带 Authorization 参数不生效问题

1. 检查接口及父级目录的 Auth 设置（Auth 优先级高于 Header）
2. 检查变量的使用
3. 检查前置脚本是否修改/删除了 Authorization

### 为什么点击 Body 的自动生成 不生效，不更新参数值？

1. 只设置了 body 参数，但未填写示例值
2. 只添加了参数，未配置示例
3. 勾选了"仅生成字段名"

在 Body 区域点击「自动生成设置」确认是否需要切换配置。

### 为什么直接使用 Apifox 生成的 curl 运行报 "URL using bad/illegal format or missing URL"？

Apifox 生成的 curl 没有自动编码。
解决：在"接口 → Params → query&path 参数"，点击参数值输入框右键"EncodeURIComponent"，再保存，接着复制 cURL。

### Apifox 是否支持 STOMP 协议的 WebSocket 连接？

目前**暂不支持**。

### 如何在文件修改后，接口直接读取修改的文件（本地文件路径以变量存储）？

1. 环境管理-变量设置
2. 接口上传文件之后，批量编辑-将文件路径替换成变量引用
3. 自定义脚本中变量替换设置

### Socket 如何使用 GBK 格式发送数据？

定位到"项目设置 - 项目资源 - 自定义函数(Socket) - Socket 请求数据处理函数"，添加：
```js
var iconv = require("iconv-lite")
var encoded = iconv.encode(data, "GBK")
return encoded
```

### 为什么参数值中的 "+" 会被解码成空格？

URL 编码规则中，空格字符在表单数据里需要编码成 `+`，`%20` 也是空格的 URL 编码形式但更长不易阅读。Web 服务器接收并解码 URL 或表单数据时会把 `+` 解码成空格。

**如何编码 `+`**：
1. 选中文本
2. 右键点击
3. 选择"自动编码"

### 如何在自定义脚本中获取变量时，同时替换该变量的变量值中的变量或动态值

使用 `pm.variables.replaceInAsync`：
```js
env_a = await pm.variables.replaceInAsync('{{env_a}}');
console.log(env_a)
```

### gRPC 请求报 "Request Exception Received message larger than max" 如何解决？

根据 [GRPC Core 文档](https://grpc.github.io/grpc/core/md_doc_statuscodes.html)，错误码是超过了最大 4M 的限制。客户端发送和接收目前有限制，无处可设置。

### 数据库连接报错，该如何排查？

1. 先用第三方数据库连接 GUI 客户端（如 Navicat）测试连接
2. 客户端连接正常时，提供配置页面截图

### 杀毒软件报毒 "openapi-generator-cli.jar" 如何解决？

误报。
1. **报毒原因**：`testingAutoload.php`（位于 openapi-generator-cli-4.3.1.jar）含 passthru 指令用于测试阶段自动初始化数据库
2. **官方来源**：https://repo1.maven.org/maven2/org/openapitools/openapi-generator-cli/4.3.1/openapi-generator-cli-4.3.1.jar
3. **解决方案**：
   - 删除本地缓存目录下的 openapi-generator-cli.jar
   - 升级到 2.7.21-alpha.1 及以上版本
   - 缓存目录：win `C:\Users\Administrator\AppData\Roaming\apifox`，mac `~/Library/Application Support/apifox`

### 为什么变量有值却取不到？

变量存在优先级，高优先级变量覆盖低优先级变量。当高优先级同名变量值为空时，低优先级变量被覆盖为空。

**优先级**（高 → 低）：临时 > 测试数据 > 环境 > 模块 > 项目全局 > 团队全局

排查：
1. 定位同名变量
2. 锁定空值来源（更高优先级路径中该同名变量是否被留空）
3. 清理或修复

### 开启兼容带注释 JSON 后仍不生效，如何处理？

1. 项目维度配置：项目设置 → 高级设置 → 启用「兼容带注释的 JSON」
2. 接口维度配置：接口 → 设置 → 启用「兼容带注释的 JSON」
3. JSON 语法校验：检查字段间缺失逗号、多余标点等原生语法错误

## 6 自动化测试

### 为什么测试场景 Apifox 客户端运行没问题，但在 Apifox CLI 或 Runner 中运行时却出错了？

最常见问题：变量使用。客户端运行时使用本地值，CLI 或 Runner 运行时默认使用远程值。

**方案一**：正确设置本地值和远程值并保持一致。

**方案二**：CLI 或 Runner 直接设置使用本地值：
- CLI：切换到 cli 新版命令，"环境/全局变量值"切换成"使用测试场景中的本地值"
- Runner：定时任务设置页可设置使用变量本地值及应用范围

### 为什么无法成功引用前置步骤数据？

- 确认在"自动化测试"模块中使用
- 切换到测试报告查看具体接口的"实际请求"标签页
- 常见原因：
  1. 是否运行了整个测试场景？（单独运行某个步骤不生效）
  2. 步骤 ID 是否正确？
  3. JSONPath 是否准确？

### 在性能测试中怎么查看实际的请求和响应？

不支持。性能测试主要评估高负载表现，应已 100% 通过功能测试。Apifox 性能测试不提供查看实际请求和响应。

### 在 Apifox 中怎么导出性能测试报告？

不支持导出，仅在 Apifox 客户端内查看。

### 如何使用数据库查询得到的数据循环传参给接口运行？

1. 添加"数据库操作"步骤，执行 SQL 查询，提取到变量
2. 添加"Foreach 循环"步骤，待循环数组设为变量
3. 在循环步骤下添加需要循环的接口，参数使用 `{{$.步骤id.element}}` 引用

### 如何解决 "Error: unable to verify the first certificate on runner" 错误？

Runner 无法验证服务器的 SSL 证书。
**方法一**：将服务器的根证书添加到 Runner 的证书列表
**方法二**：禁用证书验证：Runner 部署命令加 `-e NODE_TLS_REJECT_UNAUTHORIZED=0`

### 为什么在 CLI 执行完生成的测试报告，使用 Apifox 客户端查看报告每个 case 的详情都看不到？

CLI 命令最后添加 `--upload-report detail`。添加该参数后，测试报告在客户端打开时即可查看每个 case 详情。

### 如何在 Apifox Web 版设置通用 Runner 的服务器 Host？

由于浏览器的安全限制，Web 版无法通过 HTTPS 访问不安全的 HTTP。请前往 Apifox 客户端配置。

### 接口参数是一个上传文件在 Runner、CLI 中找不到怎么办？

Apifox 只保存文件的本地路径，不保存文件本身。
1. 把文件上传到运行测试场景的服务器上
2. 在 Apifox 中通过批量操作，将文件路径参数替换为机器上的真实路径或变量

### 当 Runner 发生问题了，如何查询 Runner 日志？

1. `docker ps` 找到出问题的 Runner
2. `docker logs --tail 100 <容器ID>` 查看日志
3. 导出日志给技术支持定位时，进入容器下 `opt/runner/logs` 目录导出 logs 文件夹

### 如何查看 runner 版本号？

进入团队/组织管理界面 → 资源 → 通用 Runner，查看状态和版本号。

### 使用 Runner 运行测试场景报错，报告提示 "unsafe legacy renegotiation disabled"？

服务器 SSL 协议过低，Runner 不兼容。
解决：`docker pull registry.cn-hangzhou.aliyuncs.com/apifox/self-hosted-general-runner:debian`

### 用自托管 Runner 执行了任务，服务器有对应测试报告生成吗？

Runner 本地不存测试报告，请在客户端内查看。

### 为什么 Linux 系统在安装 CLI 后不能直接使用？

需创建符号链接：
```bash
ln -s /home/bjz/node-v22.14.0-linux-x64/bin/apifox /usr/local/bin/apifox
```

### 为什么测试步骤同步不了接口的参数值？

从接口/接口用例导入的测试步骤，请求数据可与关联的接口同步。

- **手动同步**：点击"同步"按钮才会同步
- **自动同步**：接口变更时自动同步

> 同步的目的是保持接口结构一致，**不是更新已有的参数值**。已存在的参数值需手动更新。

### 为什么接口用例改了，测试步骤没有自动同步？

- 若步骤从接口用例导入且**复制**：用例变更时步骤不变
- 若步骤从接口用例导入且**引用**：用例变动会同步到步骤，反之亦然

如需完全同步，请选择"引用"的方式导入步骤。

### 如何在 PowerShell 中运行 Apifox CLI 命令？

PowerShell 不支持 `html,cli` 这个传参，可加引号 `'html,cli'`：
```bash
apifox run --access-token APS-xxx -t xx -e xx -n 1 -r 'html,cli'
```

### 可以给测试场景下的请求添加统一的前后置操作吗？

支持。开启步骤：项目设置 → 打开场景前后置开关。在场景详情页面添加前后置操作，运行场景时所有接口都执行相同操作。

### 自动化测试中如何让动态值在单次测试中保持一致？

动态表达式每次调用都会重新生成值。
正确做法：
1. 在前置脚本中预生成并存储变量
   ```js
   let realValueString = await pm.variables.replaceInAsync("{{$person.fullName}}");
   pm.environment.set("fixedPerson", realValueString);
   ```
2. 后续步骤引用变量 `{{fixedPerson}}`

### 如何在持续集成中选择多个测试场景一起运行？

- **方法一**：新建场景，引用这些场景
- **方法二**：使用 `-f` 命令运行指定目录

### 使用 CI/CD 是否支持通知？

- 实时运行在线数据：支持通知
- 导出数据运行：不支持通知

### 为什么使用数据库步骤查看时间数据时，与 Navicat 之类的工具显示格式不一致？

- Apifox：严格按照数据库存储的原始类型显示
- Navicat：按自身逻辑做友好化展示（如只显示日期、隐藏时间）

可使用自定义脚本步骤处理。

### 为什么 Apifox 性能测试中，实际发出的请求数与报告记录数不一致？

由"优雅关闭（gracePeriodMs）"机制引起（默认 5000ms）。

| 统计指标 | 统计范围 | 差异来源 |
| --- | --- | --- |
| 报告记录数 | 最终成功收到响应的请求总数 | 不包含被强制终止的请求 |
| 实际发出请求数 | 所有尝试发出的请求总数 | 包含被强制丢弃的请求 |

### 接口有前后置操作，导入到测试场景丢失了，如何排查？

1. 确认接口管理中操作是否已保存（在"文档模式 - 调试"页面保存属于"暂存"，不会生效，需切换到"编辑"页面重新保存）
2. 确认操作是否已启用（未启用则场景用例也默认未启用）
3. 确认导入后是否执行了同步（先导入接口、再添加前后置操作，已有场景不会自动更新，需手动点击"立即同步"）

## 7 发布 API 文档

### 怎么在发布的文档中隐藏所有 Apifox 的元素（Logo、按钮等）？

Apifox 文档内容实时更新，始终反映端内 API 文档的变化。
如不想实时变化：使用迭代分支功能，合并到主分支时才影响文档。

### 自定义域名一直显示未生效怎么办？

- 配置 CNAME 一般需要 10 分钟左右才生效
- 长时间未生效：CNAME 配置不成功、域名尚未完成备案

### 如何检查 CNAME 配置是否正确？

- Linux：`dig [你的自定义域名]`，查看 ANSWER SECTION
- Windows：需要安装 dig 命令
- 国内服务器需备案（香港除外）

### Apifox 自定义域名的 SSL 证书生成失败怎么办？

- **情况一**：证书生成失败，检查 CNAME 配置
- **情况二**：证书生成成功但无法访问，可能是电脑配置问题
  - 确认电脑时钟设置
  - 访问 ISRG Root X1 证书验证确认设备信任

### Apifox 发布文档/快捷分享中，如何让使用者修改请求的 Base URL？

通过变量实现：
1. 创建变量（如 `baseUrl`），在环境前置 URL 中用 `{{baseUrl}}` 代替具体 URL
2. 访问文档，使用者 hover 变量处会提示设置变量
3. 修改变量值，保存后路径和实际请求都自动应用更新

### 如何将 Apifox 发布文档复制到自己的项目中？

- 导出 Apifox 格式-导入项目
- 克隆

文档能否导出由拥有者设置，需在文档底部查看是否有"导出"或"克隆"按钮。

### 如何在 Apifox 在线文档中共享 Header（如 Token）？

**方法一**：在接口 Header 中直接使用变量
```js
Authorization: Bearer {{ACCESS_TOKEN}}
```

**方法二**：在全局参数中设置 Header
1. 环境管理 → 全局参数
2. 添加 Header 类型参数：
   - 参数名：Authorization
   - 类型：string
   - 默认值：Bearer {{ACCESS_TOKEN}}

### 在线文档中调试 HTTP 接口时报错 "Mixed Content request rejected"？

HTTPS 页面请求 HTTP 接口形成混合内容，浏览器主动拦截。

**解决**：修改在线分享设置中的跨域代理选项。选择"云端 Agent"、"浏览器扩展"或"自托管请求代理 Agent"模式。**不要**设置为"自动模式"或"不使用代理模式"。

### 当发布文档中图片显示 "该图片来自其他私有项目，不可访问"，如何处理？

图片从项目 A 复制到项目 B，项目 B 发布时跨项目查看图片，项目 A 非公开导致。

**解决**：
1. 项目 A 永远保持公开
2. 项目 B 该图片在链接上与本项目的 id 一致，图片重新上传到项目 B

### 分享文档请求接口报 "ELANREFUSED. The agent server refused requests from LAN hosts"？

当前默认 agent 不支持访问内网服务。部署可访问内网的 agent。

### Apifox 自定义域名自动生成 SSL 证书错误如何解决？

1. 进入自定义域名配置页面
2. 临时修改当前域名的 CNAME 配置并保存
3. 再将 CNAME 改回原配置并保存
4. 等待系统重新生成 SSL 证书

## 9 团队与项目

### Apifox 项目、团队和组织的区别

- **组织**：最大的管理单元，代表公司或大团队

```
*.apifox.cn
```

### 如何为 Apifox 中的团队配置「IP 允许访问名单」？

1. 发送邀请时，指定邀请对象参与当前团队的特定项目并设置权限级别
2. Apifox 主窗口 → 我的团队 → 成员/权限 → 项目权限，为成员设置项目层级权限

### 如何设置团队权限？

Apifox 主窗口 → 我的团队 → 成员/权限 → 团队权限，为成员设置团队层级权限。

### 如何邀请已加入团队的成员进入项目？

1. 项目管理员进入成员管理页：项目设置 → 成员管理 → 添加
2. 在弹窗中选择已加入团队的成员（支持多选），点击"邀请"
3. 注意：仅适用于已加入团队的成员。尚未加入团队的成员可通过侧边栏的"邀请成员"进行邀请

### 数据是存储在本地还是云端？可否离线使用？可否私有化部署？

- 目前 Apifox 有 **SaaS 版** 和 **私有化部署版**
- **SaaS 版**：基础功能免费，数据存储在云端，需联网
- **私有化部署版**：收费，数据存企业内部，不连外网可使用
- SaaS 版若需离线使用：可使用"离线空间"

### 购买【商业专业版】1年，使用半年后升级到【商业旗舰版】，如何计费？

升级时**仅需补差价**，不会重新计算订阅周期。按升级时剩余服务天数比例计算差额。

### Apifox Linux 桌面版下载安装

**前置准备**：
- 查看系统架构：`uname -a`
  - `x86_64`：64 位 Intel/AMD
  - `i386/i686/i586`：32 位 Intel/AMD
  - `arm64/aarch64`：64 位 ARM（如树莓派 4B、ARM 云服务器）
  - `armhf`：32 位 ARM

**安装包格式**：
| 格式 | 适用系统 | 优势 |
| --- | --- | --- |
| .deb | Debian、Ubuntu、Linux Mint、Deepin、Kali 等 | 原生适配 |
| .AppImage | 所有主流 Linux 发行版 | 免安装、便携 |
| .tar.gz | 几乎所有 Linux 发行版 | 兼容性强 |

**安装步骤**：

.deb 安装：
```bash
wget https://file-assets.apifox.com/download/Apifox-linux-deb-latest.zip
unzip Apifox-linux-deb-latest.zip
sudo dpkg -i apifox_2.7.49_amd64.deb
```

.AppImage 安装：
```bash
wget https://file-assets.apifox.com/download/Apifox-linux-latest.zip
unzip Apifox-linux-latest.zip
chmod a+x Apifox.AppImage
./Apifox.AppImage
```

.tar.gz 安装：
```bash
wget https://file-assets.apifox.com/download/Apifox-linux-manual-latest.tar.gz
tar -zxvf Apifox-linux-manual-latest.tar.gz
cd apifox-2.x.x/
./apifox
```

### Web 端与客户端数据不同步如何处理？

1. 退出 Apifox 客户端后重新运行
2. 进入项目后点击右上角的"刷新"按钮

### 为什么 Web 端或在线文档请求 HTTP 接口，Apifox 响应显示跨域，但是在客户端运行是正常的？

检查以下接口是否显示跨域：
- POST https://echo.apifox.com/anything
- POST http://echo.apifox.com/anything

如果都正常，问题在接口服务端的配置，请检查接口服务端的配置。

### 为什么下载时会跳到百度网盘或天翼网盘？

1. 所在 IP 下载次数过于频繁，触发安全限制
2. 电脑开启代理时下载会通过网盘通道（可先关闭代理）

### ApifoxAppAgent 进程的作用是什么？

实现**浏览器网页端与本地客户端之间的秒级唤醒与联动**：
- 在浏览器中打开 API 在线文档或接口协作链接
- 在 API 文档内点击 "Run in Apifox" 功能时

运行机制：
- 严格遵循操作系统的官方标准协议唤醒机制
- 运行在普通用户权限域内
- 仅在本地回环地址（127.0.0.1/localhost）安全运行
- 绝不暴露给公网

macOS 关闭：系统设置 → 通用 → 登录项；隐私与安全性 → 自动化。

### 为何 Apifox 启动会有多个 Helper 进程？

每打开一个项目会生成一个独立 Helper 进程，类似 Chrome 每个 tab 对应一个进程。
主动关闭不再使用的项目可减少 Helper 数量。

### Apifox 闪退、白屏怎么办？

**方法一**：右键点击电脑桌面菜单栏中的 Apifox 图标 → 退出后重新启动。

**方法二**：把 Apifox 拖到终端里面按回车键，下次闪退后把终端输出的最后内容发给技术支持。

### Apifox 如何打开开发者工具？

- Windows：`alt+7+8`
- macOS：`option+command+i`

### Apifox 支持 win7 吗？

兼容 32 位和 64 位 Windows 系统，支持 Intel 和 Apple 芯片的 macOS，还适用于 Linux 系统。
Windows 7、8 系统需下载对应的适配版本。

### Win 系统自动更新后打不开可能是什么原因？

更新时选择了自定义目录引发权限问题。
解决：
1. 卸载软件
2. 重新安装（**为所有人安装**）

### 为什么 Windows 安装新版本后打开还是旧版本？

更新时安装路径与旧版本不同导致同时安装了两个版本。
解决：
1. 确保安装路径一致
2. 避免同时安装多个版本
3. 验证路径是否正确

### 微信、手机号提示已经被绑定了怎么办？

1. 网页隐身窗口打开 Apifox，使用微信/手机登录账号
2. 检查该账号下的数据是否需要保留（需要保留可导出 Apifox 格式）
3. 注销完成后回到当前 Apifox 账号 → 账号设置 → 绑定微信/手机

### 为什么安装 Apifox 后启动提示 "无法定位程序输入点 DiscardVirtualMemory 于动态链接库 KERNEL32.dll"？

Windows 系统版本与 Apifox 版本不兼容。Windows 7、8 等系统需下载适配版本。

### Ubuntu 24 无法启动 Apifox，如何处理？

执行：
```bash
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
```

### Apifox 启动白屏修复方案（沙箱机制兼容问题）

1. 右键 Apifox 图标 → 属性 → 快捷方式
2. 在「目标」末尾加空格和 `--no-sandbox`
3. 应用 → 确定
4. 双击启动
